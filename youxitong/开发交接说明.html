优洗通当前系统开发交接说明

1. 交付范围

  • 本套材料以当前 fullstack/projects/youxitong 实现为依据，包含 PRD.md、index.html 交互原型及其 app.js、styles.css，并提供本说明的 Markdown 与 HTML 两种格式。前端、后端、测试共同使用同一套材料。
  • PRD 描述当前业务与用户入口；原型使用本地示例数据演示角色、页面状态与操作反馈。GitHub Pages 发布的是静态评审原型，不代表真实账号登录、资金交易、设备接入或生产服务已上线。
  • 已确认的组织建档、成员管理、账号维护及酒店、楼层、工厂站点和酒店服务关系纳入 PRD V1.3 和原型；其他未确认诉求不扩展。

2. 使用端与角色

  • 平台 Web：平台管理员、平台运营、平台财务。经营总览仅管理员和财务可见；充值仅管理员和财务可登记；平台运营不能创建平台角色账号。
  • 工厂 Web：工厂管理员、工厂操作员、工厂财务。管理员和操作员可推进履约、确认退污；财务只读查看经营总览、订单、结算和报表。
  • 微信小程序：酒店管理员、酒店操作员、司机，统一由 uni-app 移动工程构建。司机查看本人负责区域、酒店、地址及服务点，当前没有任务、定位、导航或签收操作。
  • 酒店管理员和酒店操作员均可查看补充页精确余额、提交补充订单、申请退污及使用商城。账户流水和员工账号仅酒店管理员可进入。
  • 非微信厂内终端：工厂操作员使用；与小程序共用竖屏移动端比例、采用单栏布局。微信构建不开放终端入口；首次芯片入库和租赁备货为两个工作模式。

3. 当前业务闭环

  • 平台维护组织、酒店、轻量楼层、协议价格及酒店服务关系。工厂可有多个站点，酒店最多关联一个承接站点；楼层只记录选品归属。当前服务支持平台管理员或运营按酒店和品类登记额度，但 Web 尚无对应登记页面；联调准备额度需使用现有服务能力。
  • 酒店按品类选品，有启用楼层时选择所属楼层，没有启用楼层时允许无楼层下单。切换楼层保留数量，共用酒店商品、价格和额度；服务校验有效楼层（如有）、品类额度、酒店协议价、工厂成本价、承接关系和预存余额。订单创建、额度扣减和余额扣减共同完成；失败不能留下部分成功结果。
  • 工厂管理员或操作员依次将已派单推进为备货中、配送中、已送达。平台管理员和运营仅对待派单异常订单执行派发。
  • 酒店从已送达订单的一条明细申请退污；工厂可全部同意、部分同意或驳回。同意数量按原酒店成交单价立即退款至酒店预存余额；退款不自动恢复可补额度。
  • 平台管理员或财务登记已核验的线下充值，按酒店及银行流水号防止重复入账。酒店小程序充值入口当前提示联系财务，不提供在线支付。
  • 商城使用酒店预存余额支付，提交时再次校验商品可售状态、库存及余额，同步创建订单、扣库存和扣余额。当前无商城发货、物流、收货或售后操作。
  • 终端保存手工适配器事件；首次芯片入库必须填写芯片号，租赁备货允许为空。事件用于本厂仓库汇总和扫描记录，不自动推进补充订单，不自动增加酒店额度。

4. 联调边界

  • 生产账号登录、权限校验、持久化与跨端状态更新由真实业务系统完成。原型的评审角色和页面状态选择器属于评审工具，不是业务登录或生产设置。
  • 真实项目按 youxitong-web、mobile-app、backend 分工并共享一个业务后端；PRD 与原型应作为共同验收依据，不能用原型本地状态代替服务联调。
  • 前端按角色控制入口、展示字段、可操作状态与失败反馈；后端持续校验身份、组织归属、金额、额度、库存及重复提交。工厂界面与返回数据不得暴露酒店销售金额、余额或平台毛利。
  • 终端移动端入口只接纳工厂操作员；当前后端终端服务另允许工厂管理员。此为现有入口与服务授权差异，不能据此在原型新增管理员终端入口，亦不在本次交付中擅自调整授权。
  • RFID 当前为手工适配器，无真实设备联调证据。原型事件提交成功只表示本地演示反馈，不表示硬件已读取芯片。
  • 结算当前是已送达订单工厂成本汇总，不应解释为已生成正式账单、已开票或已付款。

5. 共同验收清单

  • 逐角色核对可见菜单、字段与按钮；酒店操作员可以使用商城及查看补充页余额，但不能进入账户流水和员工列表；司机只看到本人负责范围。
  • 验证补充下单在余额不足、品类额度不足、价格缺失、楼层越权、有效承接关系缺失时整体失败；相同提交标识不得重复创建订单或扣款。
  • 验证工厂订单状态仅按顺序推进，工厂财务不可修改；跨工厂记录不可访问。
  • 验证已送达订单的单明细退污、剩余可申请数量、部分同意及驳回；服务以扣除已有有效申请后的剩余数量为准，退款金额采用原成交价并只入账一次。
  • 验证线下充值重复流水号不重复入账，金额冲突被拒绝；商城库存或余额不足不产生部分扣减。
  • 验证终端站点归属、有效品类、正整数数量、首次入库芯片号必填及重复业务引用规则；确认事件不会自动影响订单状态或酒店额度。
  • 核对 Web 正常、加载、空、失败和无权限状态，以及小程序、终端的竖屏布局、操作反馈和退出路径。原型固定采用单一显示密度。
  • 同时复核 PRD.md 与原型内嵌 PRD 一致、Markdown 与 HTML 交接说明一致。业务服务构建与联调结果需使用真实项目的验证记录，不以原型发布成功替代。

6. 账号与材料管理

  • 新建账号统一手工填写初始密码及确认密码，默认为空、支持显隐。密码为 8～20 位，英文字母、数字、英文半角特殊字符至少包含两类；任何位置均不允许空格、中文、全角字符、换行或表情，不静默裁剪。大小写字母同属一类。确认密码只在客户端校验，不发送或保存；后端独立校验初始密码并以 BCrypt 哈希保存。失败保留表单，成功或关闭后清空密码；不改变存量登录规则，不新增强制改密、找回或自动通知。账号创建与平台密码重置共同遵守 PRD 第 3.6 节；重置使目标账号原登录全部失效，停用账号不会因改密而启用。

  • 业务开发、测试和生产账号由项目负责人通过安全渠道提供，不在公共文档或原型中写入真实密码、客户隐私或生产访问凭据。

  • HTML 原型和本 HTML 说明沿用项目访问保护；file、localhost 等本地预览免密。静态页面访问保护不等同于业务系统鉴权，也不能用于保存秘密材料。

  • 交付时同时提供 PRD.md、index.html、app.js、styles.css、开发交接说明.md 和开发交接说明.html；前后端共同按当前角色及业务闭环验收。

7. 组织与账号管理交接

  • 两份需求的共同规则：单组织单角色；酒店和工厂建档必填首个管理员；组织详情添加成员自动固定组织；用户列表可查询分页；姓名、角色、启停用和密码可按权限维护。
  • 平台管理员维护全部账号；平台运营不得维护已有平台角色或授予平台角色；财务只读。自己停用、自己的管理员降级、最后启用管理员降级或停用均被拒绝，酒店最多 10 个启用账号。
  • 司机属于平台或工厂，创建时同时配置负责酒店；不允许通过普通用户创建绕过分配，不允许司机与其他角色互转。组织及登录账号不支持修改。
  • 原型组织、管理员、成员与账号列表使用同一份模拟状态；新增、维护及筛选反馈用于评审。原型不会调用生产服务，真实会话撤销、事务及并发保护必须由后端集成测试验证。
  • 原型验收包含：建酒店/工厂并继续配人，存量缺管理员补齐，组织角色联动，重复账号、非法角色、酒店名额及最后管理员限制，停启用与密码重置反馈。无权限账号仅查看，错误和空状态不能用成功提示代替。
  • 正式前端和后端接口、OpenAPI、质量门禁见下方 fullstack 交接文档；移动端既有请求保持兼容，遇已撤销会话按 401 返回登录。
  • 原型 UI 以项目现有组织、用户页面及账号、建档组件为准：组织详情采用右侧抽屉，成员区复用筛选与分页，账号维护统一入口和操作类型切换。评审专用的角色切换、页面状态和 PRD 分栏保留；模拟数据不代表生产数据。

8. 酒店、楼层与工厂站点交接

  • 酒店和洗涤厂只在“客户与组织”建档，维护模块以名称下拉框选择已建档组织，不提供新建酒店或工厂。酒店建档仅填写基本资料及首个管理员，不传新楼层，不暴露酒店内部站点名称；成功进入酒店详情。楼层在“酒店与楼层”单独维护名称、顺序与状态，每次添加一个楼层，支持停用恢复，不提供物理删除；重复名称明确报错。
  • 选品按酒店获取商品；无启用楼层时隐藏入口，订单楼层为空且展示“未指定”。有启用楼层时默认第一项并保留仍有效选择；切换保持数量。提交前楼层停用时保留草稿并提示重新选择；无可选楼层须确认后再无楼层提交。
  • “酒店服务关系”展示全部酒店，包括待配置记录，酒店详情复用同一配置操作。按名称选择工厂及其站点，更换工厂清空站点；配置、更换和解除需确认仅影响新订单，原订单承接对象及价格不变。
  • 工厂详情维护多个站点并展示服务酒店。平台管理员和运营可写，财务只读；酒店、工厂、站点停用停止新业务，旧订单继续履约、查询与退款。工厂或站点仍服务酒店时先调整或解除关系；恢复不会自动恢复已解除关系。
  • 工厂终端从本厂授权站点列表选择，停用站点禁止首次芯片入库，仅允许关联本厂本站点已有未完成订单的租赁备货。不能以原型下拉框隐藏代替后端归属及状态校验。
  • 正式服务采用版本冲突检查、下单与资料状态／关系变更的一致性控制及修改审计。新订单保存酒店、楼层、工厂、站点名称和酒店地址快照；历史回填只能反映迁移时可得资料。原型使用本地状态演示反馈，不模拟数据库锁或作为事务、资金、并发的验证证据。

9. 接口、迁移与真实项目验证

  • 本原型保留所有原业务模块，静态演示与 PRD 一并提供；业务系统的最新接口、可空楼层、幂等比较、权限、版本字段、错误码、历史快照及迁移执行步骤，以 fullstack 开发交接文档 和运行时 OpenAPI 为准。配套 fullstack HTML 交接文档 与 Markdown 同步。
  • 酒店建档兼容旧客户端楼层输入，新界面不传；选品忽略楼层分组，但旧楼层参数仍校验归属。无启用楼层时下单可省略或传空楼层，查询和重复提交必须正确处理空值。服务维护酒店内部站点及已有标识，不向界面增加酒店站点层级。
  • 迁移需先检查多地址、归属错误等异常，发现冲突停止自动合并并报告；按 fullstack 的预检及 v3 迁移指引操作。静态原型发布不执行任何业务数据库迁移，不表示既有运行库已升级。
  • fullstack 此前版本验证记录为 Web 71 项、移动端 15 项、后端 71 项测试，共 157 项通过；另完成独立 MySQL 迁移和登录后的真实页面验证。该历史记录不表示本轮重新执行这些测试或迁移；该记录属于业务代码验证，不能解释为本静态原型完成了真实资金或设备交易。Docker 未安装，相关运行检查仍是环境阻塞项。
  • 业务变更涉及金额与幂等兼容，必须完成双人人工复核后才能合并或发布正式服务；本次 GitHub 业务代码以待审分支交付。原型发布与正式服务合并、数据库迁移及上线是独立动作。
  • 原型专项验收：无楼层建档及选品、单条楼层添加、重名与排序、切换保留数量、停用恢复、全部酒店关系查询、工厂站点联动、解除确认、财务只读及旧订单历史展示。真实资金、额度、并发和幂等继续以 fullstack 集成测试为准。

10. 组织入口与单条楼层维护

  • 酒店与楼层和洗涤厂与站点仅选择、维护“客户与组织”已有的酒店或洗涤厂，不新增组织；新增楼层采用单名称输入，新增站点仍在对应工厂详情进行。
  • 酒店、洗涤厂和站点等已有档案均使用名称下拉选择，打开即可浏览候选，输入仅用于可选搜索，不要求输入编号，不允许以自由文本创建档案。候选为空时显示空状态；酒店和洗涤厂统一到“客户与组织”建档。业务页面保留字段标签、校验错误及必要操作确认，不展示原型、设计意图或规则讲解类文案。
  • 前端楼层新增提交单元素 names 数组，后端原数组能力为旧调用方保留，不将兼容能力重新展示为批量入口。
  • 验收检查组织来源、单条添加重名、已有档案下拉选择和页面文案；本轮具体检查结果见下方本地验证记录，不沿用历史结果宣称已重跑。
