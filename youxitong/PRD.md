## 1. 当前产品概述

### 1.1 产品定位

优洗通用于连接平台、酒店和洗涤厂，当前围绕布草补充、酒店服务关系、工厂履约、退污退款、预存账户、易耗品商城和厂内扫描事件开展业务。

当前产品由一个共享业务服务支撑多个使用端：

- 平台与洗涤厂人员使用 Web 管理端。
- 酒店管理员、酒店操作员和司机使用微信小程序。
- 工厂操作员可在非微信构建的厂内终端中登记扫描事件。

### 1.2 当前业务闭环

1. 平台维护酒店、洗涤厂、站点、布草价格和酒店服务关系。
2. 平台管理员或平台运营按酒店和布草品类设置额度上限。
3. 酒店选择布草品类，有启用楼层时选择所属楼层，系统校验当前额度、预存余额、价格和承接工厂后生成补充订单。
4. 补充订单生成时同步扣减品类额度和酒店预存余额。
5. 工厂终端选择订单所属站点和待备货订单，按订单品类分批登记备货；工厂管理员或工厂操作员依次推进备货中、配送中和已送达，所有品类备齐后才允许出库进入配送中。
6. 酒店可在送达24小时内一次提交本单多品类退污，经工厂整单确认及全部入库后自动退款。
7. 工厂确认可退数量后，系统按原订单酒店单价立即将退款计入酒店预存余额。
8. 酒店管理员和酒店操作员可使用预存余额购买平台商城商品；提交时同步校验并扣减库存与余额。

### 1.3 范围与使用约束

- 本文以当前系统为功能基线，覆盖已有页面、角色入口、操作规则和数据口径。
- 可补额度登记属于已有业务能力，通过“酒店档案”的独立额度弹窗设置额度上限，不设置单独菜单。
- 司机端当前只读查看负责范围；厂内终端当前采用手工事件采集方式，不代表已经接通真实 RFID 设备。
- 本期不包含在线充值、自动支付、司机任务履约、工厂付款、商品上下架。删除仅用于符合第 3.7 节条件的基础资料，业务凭证与汇总不可删除。
- 组织建档、成员入口、账号基础维护及酒店、楼层、工厂站点和服务关系维护属于已确认范围；其他未确认目标能力不属于本文范围。

### 1.4 布草归属与待确认边界

- 布草品类为平台共用目录，不属于某一个站点；酒店售价按酒店和品类配置，当前工厂成本按洗涤厂和品类配置，同厂站点共用成本。
- 工厂拥有多个站点；酒店服务关系明确承接工厂及具体站点。订单保存下单时的工厂、站点、酒店地址和价格，履约沿用原单，不随之后改名或关系变更重新归属。
- 逐件布草的芯片资产归属、重复初始化、酒店绑定或换绑以及脏布草入库自动增加额度尚未形成完整业务闭环，当前不将品类选择或备货事件等同于实物绑定。
- 是否改为各站点独立成本价待确认；当前维持洗涤厂和品类口径，不由站点选择隐式改变历史价格。
- 司机本期没有签收或送达确认操作，送达由有权限的工厂人员确认。

### 2.4 组织与数据范围

- 酒店账号只能访问所属酒店的楼层、额度、订单、退款、账户和员工数据。
- 工厂账号只能访问所属洗涤厂的订单、退款、仓库、扫描、结算和报表数据。
- 司机只能查看分配给本人的负责范围。
- 平台角色可查看全平台业务数据，但具体写操作仍受角色权限限制。
- 工厂订单页面只显示原工厂应收、退污扣减、工厂净应收，不显示酒店扣款、酒店退款或平台毛利。
- 酒店小程序只显示酒店成交价格，不显示工厂成本和平台毛利。

## 3. 全局产品规则

### 导航与管理归属

- 工厂结算展示：不展示标题下的统计口径说明段，保留结算表格及原金额、退污扣减和净额；统计范围及计算规则不变。
- 页面标题规则：仅保留业务主标题，移除“WORKSPACE”及标题下的通用说明副标题；业务分区名称、统计范围、字段标签、校验错误和操作确认继续展示。
- 站点管理弹窗：标题为“站点管理”，不在标题上方重复展示工厂名称；内容区保留当前工厂名称。
- 工厂关系操作名称：酒店档案中的原“更换承接”“解绑承接”统一为“更换工厂”“解绑工厂”，弹窗标题同步；仍选择工厂及其站点，确认、引用保护和对历史订单的影响保持原规则。
- 档案行操作：酒店档案、工厂档案的“成员”“协议价”统一放入“更多”菜单，保留原有组织预选和返回上下文。只读角色仍可从更多进入查看，编辑与删除继续按原权限隐藏。
- 更多操作规则：列表操作列的“更多”在鼠标悬停时展开小菜单；点击和键盘也可打开，触屏可点击。鼠标移入菜单或焦点位于菜单内时保持打开，离开后关闭，按退出键可关闭；权限、禁用状态及删除等操作的确认规则不变。
- 导航规则：平台按管理对象组织功能，经营总览独立置顶；业务管理含业务订单、退污退款；酒店管理含酒店档案、酒店成员、酒店协议价；工厂管理含工厂档案、工厂成员、工厂协议价；配送管理含司机管理；财务管理含钱包与流水、工厂结算；商城管理含商城商品、商城订单；系统管理含平台成员。
- 权限规则：按现有角色过滤菜单，无可见菜单的分组隐藏。工厂侧按业务管理、生产管理、经营分析组织订单与退污、仓库与扫描、总览与报表；所有工厂角色均不显示工厂结算、酒店售价与平台毛利。
- 图标规则：二级菜单采用语义明确的图形图标配合菜单名称，不以单字充当图标；选中与未选中状态清晰可辨，收起侧栏后仍可通过提示及辅助标签识别菜单。
- 列表默认与搜索：有筛选条件的列表默认显示当前权限和模块范围内全部数据，按既有分页展示，不要求先选择条件。具备关键词查询能力的列表提供明确搜索框；组织、关键词及状态合并为一组筛选，不重复渲染同一条件。重置恢复默认全部；从档案等上下文入口进入时允许带入明确对象条件。
- 导航交互：菜单、页面标题与当前位置名称一致；侧栏折叠后可查看完整名称，短屏可滚动；旧入口按对应酒店、工厂上下文进入新模块，没有上下文的组织入口进入酒店档案。平台组织不出现在两类档案中，平台账号由平台成员维护。
- 工厂成员范围：只展示工厂管理员、工厂操作员、工厂财务，不列司机，角色筛选与新增候选均不含司机；司机新增、编辑、启停用、改密和删除统一从司机管理进入。司机仍归属工厂，账号与负责酒店数据不迁移、不复制，原有操作权限和保护规则不变。
- 成员导航：酒店成员与工厂成员分别作为二级菜单。组织选择器仅列对应类型，可搜索；默认组织条件为全部，展示当前模块组织类型的全部成员，不展示其他类型组织的账号。切换组织重新加载并清除上一组织成员状态，旧读取结果不得覆盖当前选择。平台财务只读，管理员和运营沿用现有账号维护权限及最后管理员保护；平台账号仍从平台成员维护。
- 关联交互：档案中的协议价入口预选当前酒店或工厂；返回恢复原档案查询条件。酒店档案与工厂档案分别保留查询状态，不混用结果；切换对象后旧读取结果不得覆盖当前对象。


### 3.1 登录、退出与会话

- Web 与小程序均使用业务账号和密码登录。
- 登录成功后按账号角色进入对应工作台。
- Web 账号不能进入酒店或司机小程序工作台；不适用的账号登录后返回登录页并提示使用 Web 管理端。
- 已登录用户再次进入系统时恢复当前会话；会话失效后返回登录页。
- Web 右上角显示组织名称、当前角色、用户头像缩写和用户姓名，并提供退出登录。
- 酒店小程序在“我的”页提供“退出登录”按钮；司机工作台顶部提供“退出”按钮，两者均直接退出，不弹出二次确认。
- 退出后结束本次会话，清除当前用户身份并返回独立的“业务账号登录”页；不能通过返回继续使用刚才的工作台。即使本次注销未成功，也清除本机登录状态并返回登录页。
- 退出后的登录页展示优洗通、账号与密码输入框、登录按钮及业务账号使用说明，不显示酒店底部导航。账号、密码初始为空，不提供角色选择器；账号提示“请输入平台开通的账号”，密码提示“请输入密码”并隐藏输入内容。
- 账号去除首尾空格后为空，或密码为空时，显示“请输入账号和密码”；登录中按钮禁用并显示等待状态，失败在表单内展示原因。重新登录后根据该账号角色进入酒店补充页或司机工作台，不继承退出前的商品选择。
- 登录说明为“首版使用已开通的业务账号。微信绑定及支付将在客户资质就绪后开放。”，不提供微信绑定或微信支付入口。

### 3.2 加载、空数据、错误与无权限

- 页面读取数据时显示加载状态。
- 列表无记录时显示对应业务空状态。
- 读取失败时显示简短错误原因和重新加载入口。
- 无页面权限时不显示菜单；通过外部地址进入时显示无权限页面。
- 提交失败时保留当前页面并显示可理解的失败原因。

### 3.3 列表、筛选与分页

- 酒店、洗涤厂和站点等已有档案均使用名称下拉选择，打开即可浏览候选，输入仅用于可选搜索，不要求输入编号，不允许以自由文本创建档案。候选为空时显示空状态；酒店和洗涤厂分别到“酒店档案”和“工厂档案”建档。业务页面保留字段标签、校验错误及必要操作确认，不展示原型、设计意图或规则讲解类文案。

- Web 业务订单支持下单时间、酒店、工厂和状态查询；退污退款支持酒店、布草和状态查询，默认每页 20 条。
- 钱包流水默认展示全部酒店，选择或清空酒店立即生效；酒店协议价与工厂协议价分页面展示。
- 状态筛选为单选，默认“全部状态”；选择或清空后点击“查询”生效，并回到第一页。提交后的自动更新保留当前筛选和页码；订单与退款页没有独立重置按钮；组织和用户管理提供重置。
- 钱包酒店条件为可搜索名称下拉框，默认全部，选定后精确匹配，选择或清空立即生效并回到第一页，无需点击查询。无酒店条件不展示余额。协议价格的两类组织相互独立，不使用酒店与洗涤厂的交集作为设置条件。
- Web 用户、业务订单、退污退款、钱包流水、商城订单和 RFID 扫描记录使用分页；其余通用资源页一次显示当前返回的全部记录，不提供可切换页容量或列头排序。
- 酒店布草订单、退污记录及厂内终端最近事件当前仅展示最近 20 条，不提供翻页或加载更多。酒店账户的充值申请与资金流水支持每页 20 条分页。不得将单页记录数视为历史累计总量。
- 所有页面不提供独立刷新按钮；进入页面自动加载，提交成功后自动更新相关列表、详情与统计。查询、重置及加载失败后的重试保留。
- 组织和用户使用专用管理页面，支持组织详情及账号维护；酒店档案、工厂档案提供下述专用维护能力；未另行说明的通用资源页不提供详情、编辑、停用或批量操作；基础资料删除统一遵守第 3.7 节。

数据排序规则：

- 订单、退款、钱包流水、商城订单与扫描事件按各自创建或发生时间倒序；相同时间没有另行规定次级顺序。
- 组织按组织类型、组织名称升序；酒店按名称升序；价格和仓库按布草品类名称升序；商城商品按种类、名称升序；工厂结算按工厂名称升序。
- 未提供条件的页面不涉及用户筛选；单条详情和表单不涉及排序。

单对象详情展示规则：

### 3.6 创建账号与初始密码

- 适用范围：平台新增用户、酒店或工厂建档时创建管理员、新增司机、酒店管理员添加员工，以及平台重置密码。

- 校验规则：先检查初始密码是否合规，再检查确认密码是否填写且与初始密码逐字一致；校验失败保留表单并显示原因，不创建账号。
- 交互规则：提交中阻止重复提交；创建失败保留输入供修改，成功后关闭或清空表单并刷新账号数据。取消、关闭或重新打开表单后不保留密码。成功反馈不回显密码。
- 数据规则：初始密码由创建人手工设置；确认密码只用于当前表单核对，不作为账号资料保存。创建成功后，由创建人通过安全渠道告知使用者账号及初始密码；当前没有短信或邮件自动通知。
- 使用边界：现有账号继续按原密码登录；没有首次登录强制改密或找回密码入口。平台可按账号维护权限重置密码，并使目标账号原登录失效；不会自动重置其他存量密码。
- 验收标准：账号创建与重置入口均拒绝少于 8 位、超过 20 位、仅含单类字符、含空格或中文、确认不一致的密码；字母加数字、字母加特殊字符、数字加特殊字符或三类组合均可通过格式校验。失败不清空输入，成功或关闭后清空密码。不涉及密码筛选或排序。

### 3.7 基础资料删除

- 适用范围：平台管理员和平台运营可在组织、酒店、洗涤厂、工厂站点、楼层、账号、司机、商品及商品种类列表清理误建且无业务引用的资料。无权限角色不显示删除按钮；平台运营不能删除平台权限账号。
- 交互规则：逐条删除，不提供批量删除；确认前展示对象与影响，取消不变更。提交中禁止重复操作；遇引用、保护规则或对象已变化时拒绝操作并说明原因；成功关闭相关详情、刷新列表及关联候选，保留原筛选，无结果展示空状态。
- 引用保护：已有订单、资金流水、额度、扫描记录、协议价格或服务关系的组织不可删除。非零余额、成员有登录会话或历史业务操作的组织不可删除；无业务空组织可连同无业务成员、楼层、地址及零余额空账户清理，创建与删除记录仍可追溯。
- 单项保护：楼层已有订单不可删除；站点已有服务关系、订单或扫描记录不可删除；账号有登录会话、业务或操作历史不可删除，当前登录账号和最后一个启用管理员不可删除；平台组织不能删除。司机删除按账号规则，并同时清理其负责酒店分配。
- 商品保护：种类已被商品使用不可删除；商品已被商城订单使用不可删除。
- 保留范围：订单、退污退款、钱包流水、审计和扫描凭证不可删除；库存、结算、报表为汇总，不提供删除汇总行。协议价格继续通过调价维护；已有历史资料可使用适用的停用功能。
- 验收标准：无引用误建资料删除后各入口同步；带业务引用资料被拒绝且原数据不变；删除自己、平台组织及最后管理员均被拒绝；订单、资金与扫描记录继续可查。

### 3.11 退污成本与净额

- 展示规则：酒店订单列表仅对存在退污记录的订单展示原订单金额、已退金额、净支付及已通过退污件数摘要；无退污记录时隐藏整组摘要，保留卡片原件数、原金额和操作按钮。待检测、已通过或已驳回记录均满足展示条件，不以退款金额大于零判定。详情继续并列显示上述金额与件数；工厂订单显示原工厂应收、退污扣减和净应收；平台订单显示两侧原额、退款或扣减、净额以及平台净毛利。没有已通过退污时退款与扣减显示零，净额等于原额；原件数不变。
- 计算规则：酒店已退金额按已通过退污实际入账退款汇总，净支付等于酒店原额减已退金额；工厂退污扣减等于各明细已通过数量乘以原订单工厂成本单价之和，净应付等于工厂原额减扣减；平台净毛利等于酒店净支付减工厂净应付。
- 历史规则：追溯全部历史已通过退污，按原订单归属汇总；待检测、已驳回及部分同意中的未通过数量不参与金额扣减。原酒店销售价和原工厂成本价均使用下单快照，不随当前价格调整。历史快照缺失、退款重复或通过数量异常时显示数据异常并核查，不使用现价或零金额代替。
- 交互规则：退污确认成功后刷新订单、详情、总览、结算与报表；查询或再次进入时使用最新汇总。原型同一申请重复审核不会重复入账或重复扣减。
- 统计边界：经营总览含已派单、备货中、配送中、已送达；工厂结算仅含已送达；业务报表累计订单数与累计原件数含全部本厂订单，通过退污件数与金额仅含已送达。经营总览按所选日期范围统计，结算与业务报表保持截至当前的历史范围；不提供结算周期、付款、跨期账单或资金划拨。
- 权限规则：酒店仅看本酒店销售及退款数据；工厂仅看本厂成本、扣减与应收，不能查看酒店售价和平台毛利；工厂结算模块仍仅平台可见。
- 验收示例：100 件，原酒店单价 8 元、原工厂成本价 5 元，通过退污 10 件时，酒店原额 800 元、已退 80 元、净支付 720 元；工厂原额 500 元、扣减 50 元、净应付 450 元；平台净毛利 270 元。

- 模块目标：对应的酒店或工厂档案是各自建档、资料编辑与成员管理入口。创建时完成首个管理员配置；查看资料、成员管理和资料编辑分别进入独立界面。
- 列表入口：组织列表展示编号、名称、类型和状态；行操作分别提供“详情”“成员”“编辑”，受保护删除仍遵守第 3.7 节。点击名称或“详情”仅查看组织资料，点击“成员”进入所属管理模块的独立成员页面并预选当前组织，点击“编辑”打开独立资料表单，不共用混合详情页面。缺少启用管理员的存量组织显示“待配管理员”，不把它当作停用状态。
- 详情规则：以描述卡展示只读组织资料，包含编号、名称、类型和状态，酒店另展示区域和地址；空值显示“—”。不显示成员列表、新增成员、资料编辑或楼层维护操作。关闭详情保留组织列表查询条件；单对象资料不涉及筛选或排序。
- 筛选规则：组织名称为可清空文本，按名称模糊匹配；组织类型由所在档案模块固定，不提供跨类型筛选。条件取交集，点击查询或回车生效，重置清空条件。组织按类型、名称升序，同名按组织编号稳定排序。
- 建档步骤：从“新建酒店”或“新建工厂”打开表单，组织类型由当前入口固定，然后依次填写首个管理员、确认创建。酒店与洗涤厂均必须配置首个管理员；平台组织不提供普通新建入口。
- 字段规则：酒店名称、区域和地址必填，不填写酒店站点名称及楼层，也不强制选择承接站点。洗涤厂仅填写工厂名称，不填写首站点、区域或地址；站点资料从工厂列表“站点”入口独立维护。两类组织均必填管理员姓名、登录账号、初始密码及确认密码，角色只读为对应组织管理员。普通文本去除首尾空白，密码不裁剪；表单字段不涉及排序。
- 数据规则：酒店同时建立档案、零余额账户和管理员，不自动生成楼层；工厂仅建立组织和管理员，不自动生成站点。任一资料或账号校验失败，全部创建失败，不留下部分组织或账号。零站点工厂可正常建档，须另建启用站点并配置酒店承接关系后才能承接新订单。
- 交互规则：前后步骤保留已填资料；确认页展示组织名称、管理员姓名和账号，酒店另展示区域和地址，不展示密码。提交中禁止重复操作；失败保留表单并说明原因；酒店创建成功进入酒店详情，工厂创建成功进入组织详情。取消或关闭时清空密码。
- 资料编辑：平台管理员和平台运营从对应的酒店或工厂档案列表的“编辑”打开独立表单，不从只读详情进入。酒店可修改名称、区域、地址和状态；洗涤厂可修改名称和状态，站点区域与地址仍在站点维护。组织编号和类型不可修改；平台组织不提供编辑入口，财务不显示编辑按钮。打开时读取最新资料；必填校验失败或保存冲突时保留输入并提示；取消不保存，提交中禁止重复操作，成功关闭编辑表单、刷新组织列表，下次打开详情展示最新资料。停用洗涤厂前必须调整或解除当前服务酒店关系，已有订单继续履约，恢复不重建已解除关系。
- 成员入口：酒店管理和工厂管理分别提供“酒店成员”“工厂成员”二级菜单。页面默认展示对应组织类型的全部成员，组织、关键词、角色和状态合并为一组筛选；档案中的“成员”快捷入口带入当前组织。新增或维护账号时所属组织固定，不允许跨组织修改。存量缺管理员组织在成员页面补齐对应管理员，不自动生成密码或账号；从档案进入后可返回原档案列表并恢复查询条件；不进入组织资料详情。
- 数据与统计规则：成员按所属组织纳入，包含启用和停用账号；启用管理员只统计本组织对应管理员角色且状态为启用的账号，按账号去重，不受当前列表筛选或日期影响。成员变更后刷新成员页面、组织列表的管理员状态和相关账号列表，零成员显示零，读取失败显示错误及重试，不以零代替失败。
- 权限规则：平台管理员、平台运营可以创建酒店或工厂；成员维护范围按下述账号管理规则执行。无创建权限时隐藏新增入口，组织详情仍可只读查看。

### 4.5 酒店档案

#### 额度上限与净入库

- 展示规则：酒店档案逐品类展示额度上限和当前可下单量。上限独立设置；当前可下单量只读，零上限有效。
- 交互规则：平台管理员、运营设置额度上限；不设置期初数量，不提供核定入口。没有有效入库时可下单量为零，初始入库50、未下单且上限不少于50时可下单50。
- 数据规则：可下单量＝配置上限与“新增日常回收入库＋新增退污入库－新增下单数量”非负值的较小者。下单数量包含待备货订单，既有订单继续履约，不重复扣减新口径额度。
- 入库超过上限的部分仍完整记录；上限调整不直接授额、不撤销原订单。备货将未备货占用转为累计出库，不再次扣可下单量。所有数量按酒店、品类核算，跨楼层及换厂延续。
- 历史规则：原额度配置只作为上限衔接，不作为初始可下单量。新口径累计量从有效酒店入库及新下单记录形成；无法归属的历史入库不猜测授额，既有订单、资金和历史流水不重放。
- 校验与反馈：数量为非负整数，版本冲突需重读核对；入库与下单并发不能超额，同一提交重试只生效一次。财务只读，不可修改上限。
- 验收：日常入库50、下单40时可下单10；退污入库5后累计入库55、可下单15，仍受上限限制。

- 模块目标：统一管理酒店建档、资料、成员、楼层、可补额度和承接站点服务关系。楼层仅作为酒店内部选品归属标签，不是配送地址，不参与派厂、商品范围、价格、额度或结算。
- 列表展示规则：展示酒店名称、区域、酒店地址、状态、启用楼层数、承接工厂及站点；未关联显示“待配置”，与停用状态分别展示。酒店名称进入详情，关闭详情保留查询条件。
- 筛选规则：酒店为可清空下拉框，默认全部，候选来自对应的酒店或工厂档案已建档酒店，可选按名称搜索，选定后精确匹配；状态单选全部、启用、停用；关联站点单选全部、已配置、待配置，默认全部，条件取交集。查询或回车生效并回第一页，重置清空条件；无结果提示调整条件，失败可重试。
- 数据规则：酒店按名称升序，同名稳定排序；楼层数仅统计当前酒店启用楼层，按楼层计一次，不受日期或其他酒店影响，维护后刷新；无楼层显示零。列表包含未配置承接站点的酒店。
- 酒店档案提供“新建酒店”，资料、成员、楼层、额度和承接关系分别独立维护；低频操作归入“更多”，解绑与删除分别确认。
- 建档规则：对应的酒店或工厂档案建档仅填写酒店名称、区域、地址及首个管理员姓名、账号、初始密码和确认密码；不出现楼层、酒店站点名称。允许暂不指定承接站点，成功进入酒店详情，不自动生成“默认楼层”。
- 详情边界：从酒店名称或列表“详情”进入只读详情，展示酒店信息、楼层信息及承接工厂和站点。酒店信息包含名称、区域、地址和状态；楼层展示名称、顺序和状态；无承接关系显示“待配置”。详情不包含资料编辑、成员管理、楼层维护、更换、解绑或删除操作；名称、地址及酒店启停用统一在对应的酒店或工厂档案编辑。配送仍使用酒店地址，酒店停用不阻断旧订单履约和退款。

**酒店列表独立操作规则**

- 行操作保留详情、楼层和额度等常用入口；成员与协议价统一从“更多”进入，编辑、工厂关系及删除按各自入口执行；未配置承接关系时显示“配置”代替“更换”，不显示“解绑”。详情始终只读；财务仅可查看，不显示编辑、解绑及删除操作。
- “楼层”打开独立楼层管理弹窗，固定当前酒店，提供原有新增、编辑、排序、启停用及受保护删除；不在此弹窗编辑酒店资料或承接关系。关闭返回列表，成功后自动更新楼层数及后续详情。
- “配置”或“更换”打开独立选择弹窗，固定酒店，选择启用工厂及其启用站点；切换工厂清空原站点。更换展示原承接对象，保存前明确只影响新订单；取消不修改，失败保留选择，成功关闭并自动更新列表。
- “解绑”打开独立确认，展示酒店及当前承接工厂、站点，说明解绑后新订单不可提交、旧订单仍按原关系履约。取消无变化；确认时校验最新关系，成功后列表改为“配置”，不再显示“解绑”。
- “删除”打开独立保护确认，不与解绑共用确认。展示删除对象，说明仅无业务引用基础资料可清理；订单、资金、额度、成员会话及其他历史引用仍按原保护规则阻止删除，不得自动解绑后强删。成功后自动更新列表，失败保留原数据并说明原因。
- 所有提交中禁止重复操作；只读详情不放置上述管理按钮，关闭各弹窗保留列表筛选。酒店信息及承接对象使用描述卡，楼层多条记录使用只读列表；无楼层显示空状态，读取失败不可当作无楼层或未配置关系。

**额度上限独立弹窗**

- 酒店档案“额度”打开当前酒店的布草上限及可下单量；上限非负整数，可下单量只读。点击“设置上限”回填现值，提交失败保留输入，冲突需重新读取后核对。
- 上限只限制可下单量，不直接授额；累计日常回收加退污入库减下单占用决定动态额度。零入库不能下单，不设置期初数量。下单仍校验双价格、有效服务关系和余额。

- 楼层字段：名称必填，去除首尾空白；顺序为整数，数值越小越靠前，同序按名称排列；状态为启用或停用。只提供名称、顺序、状态，不配置地址、工厂站点、独立商品、价格或额度。
- 楼层操作：每次添加一个楼层，名称采用单行输入，不按逗号或换行拆分；支持改名、修改顺序、停用、恢复和删除；已有订单引用的楼层拒绝删除，可改用停用。列表包含启用与停用记录；同酒店内名称唯一，与已有启用或停用记录重名均明确指出并阻止保存；与停用项重名时提示恢复原楼层。
- 操作反馈：平台管理员和运营可维护楼层及服务关系；财务只读，不显示写操作。保存中禁止重复提交；失败保留输入；楼层或关系已被他人修改时提示重新打开加载最新资料后重试，不覆盖他人结果。楼层停用前确认对象及对新选品的影响，成功后自动更新详情与列表，修改记录可追溯。
- 承接关系：只从本模块列表进入独立配置、更换弹窗或解绑确认，不在详情中操作，也不设置独立“酒店服务关系”菜单。
- 验收标准：从对应的酒店或工厂档案无楼层建档后可进入维护详情；维护模块只能选择已有酒店；酒店详情只读展示酒店、楼层和承接信息，所有维护操作从独立列表按钮进入；可筛选未关联酒店；单条添加重名明确报错；排序、停用与恢复同步影响选品候选，不改写旧订单所属楼层。

#### 承接站点配置

- 业务关系：工厂可以有多个站点，每家酒店最多关联一个承接站点，一个站点可服务多家酒店。平台统一维护关系。
- 展示规则：列表展示全部酒店，包括未配置酒店；字段包括酒店、酒店状态、承接洗涤厂、工厂站点和关联状态。未关联显示“待配置”，不展示酒店内部站点层级。
- 筛选规则：酒店名称下拉选择，可选搜索候选，酒店状态与是否关联站点单选，默认全部；条件取交集，查询回第一页，重置清空。按酒店名称升序；无结果展示空状态，读取失败可重试。
- 设置规则：酒店、工厂和站点通过名称下拉选择，打开即可浏览候选，输入仅用于可选搜索；从列表“配置”或“更换”进入时酒店预填且固定。仅可选择启用工厂及其启用站点，切换工厂必须清空原站点；候选为空时说明原因并引导维护。
- 操作规则：未配置酒店显示设置，已配置显示更换和解除。保存前确认酒店、原承接对象与新承接对象；解除前确认当前关系。明确说明仅影响新订单，已有订单保留原承接对象和成交价格。
- 数据规则：新补充订单使用提交时有效的服务关系自动派发；未配置承接工厂时无满足双价格的选品候选，提示联系平台配置承接关系；关系无效时下单不可用。恢复酒店、工厂或站点不自动恢复已解除关系。
- 权限与冲突：仅平台管理员、平台运营可写，财务只读。提交中禁止重复操作，失败保留选择；他人先修改时提示重新打开加载最新候选后重选，不覆盖新关系。成功后自动更新酒店列表、酒店详情和工厂服务酒店清单。

### 4.6 酒店协议价与工厂协议价

- 模块入口：酒店管理下的“酒店协议价”与工厂管理下的“工厂协议价”为两个独立页面。工厂协议价表示平台向工厂结算的布草单价，即工厂成本价，同厂站点共用。
- 展示规则：页面默认展示所属类型全部组织价格；组织条件为可搜索名称单选，默认全部，提供布草品类关键词搜索框。组织精确匹配、品类名称模糊匹配，条件取交集；查询或回车生效，重置恢复全部。档案进入时预选当前组织；两个价格页分别保留筛选和加载状态。
- 明细规则：逐项展示组织名称、平台启用布草名称、单位与当前单价，按组织名称、品类名称排序；未配置在价格位置显示“未设置”，已配置零价显示“¥0.00”，不另外设置“设置状态”列。金额以元显示两位小数，不涉及日期筛选。组织仅限对应类型，停用组织可查看和维护价格，但改价不恢复其下单资格；不存在或类型错误的组织不能设置价格。
- 操作规则：有写权限时，每行未配置显示“设置价格”，已配置显示“修改价格”。弹窗固定当前组织、价格类别和布草品类，已有价格回填，未配置时输入为空；显示当前价和待保存价格，不允许在弹窗换组织或品类。
- 校验规则：单价必填、非负且最多两位小数，允许零，不接受负数、非金额或超精度，不自动舍入。取消关闭不保存；提交中禁止重复操作；失败保留输入与错误原因，成功关闭并更新当前组织价格。
- 异常规则：组织候选和价格列表分别展示加载、空状态、错误及重试；查询新条件时明确加载状态，旧结果不能覆盖新查询。启用布草为空时展示“暂无启用布草”；候选为空时引导有权限用户到对应档案建档。
- 数据规则：酒店协议价按酒店与布草品类独立维护；工厂协议价按工厂与布草品类独立维护。修改仅影响新订单，一类价格变化不修改另一类，历史订单、退款和结算沿用原价格。
- 权限规则：平台管理员与运营可设置和修改；平台财务只读，不显示设置按钮。工厂角色不进入平台协议价管理页面。
- 验收标准：默认展示全部对应类型组织价格，可按组织和品类查询；未设置与零元区分；弹窗对象固定、现价回填正确；取消和失败不改变数据，快速切换不串组织，重复点击不重复提交；改价不影响历史订单。

### 4.7 工厂档案

- 工厂档案提供新建工厂、只读详情、独立资料编辑、成员及站点管理入口；低频删除归入“更多”，沿用引用保护和独立确认。站点管理固定工厂，站点删除仍在站点管理内执行。
- 站点管理：固定当前工厂，展示多条站点与原有管理操作，站点删除继续执行引用保护及独立确认。无站点显示空状态；财务只能查看，维护按钮按原权限隐藏。取消无变化，提交防重，成功后自动更新列表及后续详情。

- 展示规则：工厂列表通过下拉框选择对应的酒店或工厂档案已建档洗涤厂，可选按名称搜索，并支持状态筛选，默认全部，条件取交集；工厂按名称升序。工厂列表操作列仅提供独立“详情”“站点”入口。详情以只读描述卡展示工厂基本信息，以只读列表展示站点名称、区域、地址、状态和服务酒店，不包含站点管理操作；“站点”打开独立管理弹窗。工厂基本信息不得使用单行数据表格模拟详情。
- 字段规则：工厂名称必填，状态为启用或停用；新增站点名称、区域、地址必填，默认启用。站点从当前工厂读取，服务酒店只统计当前关联该站点的酒店，按酒店去重；零酒店显示零或“暂无服务酒店”，读取失败不当作零。
- 工厂档案提供新建工厂、只读详情、独立资料编辑、成员及站点管理入口；低频删除归入“更多”，沿用引用保护和独立确认。站点管理固定工厂，站点删除仍在站点管理内执行。
- 停用规则：工厂或站点仍有服务酒店时，必须先调整或解除关系，展示受影响酒店。停用后停止新业务，但既有订单继续查询、履约和退款，不自动改派。
- 历史规则：新订单记录当时的酒店名称、所属楼层、工厂、站点及酒店地址，后续改名或改地址不改变历史展示；原有订单补齐历史资料只能反映补齐时可得资料，不能保证还原更早时点。
- 验收标准：一厂多站点、一站点多酒店正确展示；候选按工厂联动；设置、更换、解除后各入口一致；有服务酒店不能停用，解除后可停用和恢复，恢复不重建关系；旧订单承接对象、价格和地址保持不变。

### 4.8 司机管理

- 平台管理员、运营统一在司机管理创建账号和维护负责范围，司机属于工厂，不出现在工厂成员维护入口。
- 新建与编辑负责范围均必填区域文字，最多120字；可选择多家酒店。每个司机与酒店只保留一条分配，支持追加、调整及移除，整体校验后共同保存。
- 新建及启用状态司机至少保留一家负责酒店；账号创建和初始分配共同成功或失败。
- 司机小程序只展示本人负责范围：顶部显示负责区域文字详情，下方按区域分组列出酒店及已有地址；移除区域数、酒店数统计卡片，不增加任务状态或配送确认操作。
- 加载失败可重试；无负责酒店明确显示空状态。越权读取、空区域及重复酒店分配均被阻止。

### 4.9 钱包与流水

- 酒店管理员充值：填写金额、必填银行流水号及可选备注。金额大于零且最多两位小数，流水号保留前导零及分隔符；提交后待审批，余额不变。酒店操作员不办理充值。
- 财务审批：平台管理员、财务在申请列表和详情只读查看酒店提交的流水号，不另行输入或修改。核实到账后通过，或填写原因驳回。历史待审批申请缺少流水号时禁止通过，应驳回后由酒店重新提交。
- 平台直接充值：钱包与流水的“登记充值”选择酒店、金额和可选备注，确认后直接增加余额并追加流水，不需审批，不填写或关联银行流水号。只有平台管理员、财务可操作。
- 数据规则：酒店申请审批通过才入账，同一银行流水不能跨申请或酒店重复入账。直接充值通过独立业务记录防重复；重复点击和超时重试均只能增加一次余额，失败不产生部分余额变动。
- 记录展示：酒店提交的银行流水号在申请及详情回显；平台直接充值无审批和银行号，不伪装为历史待审批。手机审批通过申请与对应流水合并展示一次，待审、驳回仍保留；历史已入账记录不改写。
- 筛选规则：Web 默认全部酒店记录，选酒店后显示该酒店余额；申请可按状态筛选，各列表独立分页。手机只看本酒店，按发生时间倒序；空数据和失败有明确反馈。
- 验收：酒店申请后不增余额，审批通过仅增一次；财务不能改流水号，重复银行号被阻止；平台直接充值确认即入账且不新增待审记录。

### 4.10 工厂结算

- 平台管理员、平台运营和平台财务可查看；工厂相关角色不显示此模块。

- 列表字段：工厂组织编号、洗涤厂、已送达订单、原布草件数、退污通过件数、原工厂应付、退污扣减和工厂净应付。
- 原工厂应付按已送达订单原工厂成本汇总；退污扣减按其历史已通过退污数量与原成本价汇总；净应付为两者之差。
- 每家工厂一行，仅统计已送达订单，分别展示原工厂应付、退污扣减、工厂净应付；扣减追溯全部历史已通过退污，未送达订单不计入。没有已送达订单的工厂数量和金额为零；缺失快照或异常数据提示核查，不冒充零值。净应付不代表已付款。
- 当前页面仅提供汇总查看，不提供账单生成、核对、开票或付款操作。

### 4.11 商城商品与商城订单

商城商品：

- 权限与入口：仅平台管理员和平台运营显示，提供新增商品、编辑、种类管理与受保护删除；财务不显示。当前没有上下架操作。
- 列表字段：商品名称、种类、商品说明、统一售价、可售库存、状态、编辑和删除操作。列表只返回可售商品，包含零库存商品，按种类、名称升序；无记录展示空状态，失败可重试。
- 商品种类展示规则：商品表单必填单选下拉，默认未选择；候选仅来自种类管理，可按名称搜索，不允许通过输入新名称直接成为商品种类。无候选时引导先维护种类；已选种类失效后必须重选。
- 种类管理交互规则：管理弹窗仅展示种类列表、删除和“新增种类”入口，不将名称输入框嵌入列表。点击新增打开独立弹窗，名称必填，去除首尾空白，最多 80 个字，重复名称拒绝保存；取消不新增，成功关闭新增弹窗并自动更新种类列表及商品候选。列表按名称升序，不提供改名、日期筛选或统计；已有商品使用的种类不可删除并说明原因。
- 商品图片展示规则：选填，提供“上传图片”，选择本地 PNG 或 JPEG 文件，文件不超过 1MB；成功显示预览，并可更换或移除。不提供图片地址输入；未选择时商品使用占位图。
- 图片交互规则：选择失败或文件不符合要求时提示原因并保留原图；图片处理中禁止商品保存，完成后再提交；更换只更新当前表单图片，移除后回到未选择状态。图片字段不涉及筛选或排序。
- 其他字段与校验：名称、说明、统一售价和初始库存必填；售价输入明确标注“统一售价（元）”，必须大于零且最多两位小数，列表按元展示；初始库存为大于零的整数。取消不新增商品，保存中禁止重复提交，失败保留输入。
- 编辑规则：点击商品行“编辑”回填名称、种类、说明、图片和统一售价；名称最多120字、说明最多500字，均去除首尾空白且必填，种类必须仍有效，售价须大于零且最多两位小数。当前库存只读，允许编辑零库存及已有订单的商品。图片支持保留、更换、移除；取消不改动原商品。保存期间禁止重复提交，失败保留输入，成功关闭弹窗并更新列表。修改只作用于商品当前资料及后续订单，历史订单名称、成交价和金额不变；库存与商品状态不在编辑范围内。编辑不新增筛选、排序或统计规则。
- 删除规则：商品无商城订单引用时可删除，有订单引用时拒绝删除；成功后自动更新商品及种类选择候选，被引用种类在商品清理完成前仍不可删除。
- 验收标准：编辑后重新打开及酒店商城显示新资料；取消和校验失败不改变商品；零库存与已有订单商品可编辑，历史订单及库存不变；空种类不能保存商品；先建种类后可在下拉选中，不能自由输入代替选择；本地选图可预览、更换、移除；被商品使用的种类、被订单使用的商品均不可删除。

商城订单：

- 平台管理员、运营和财务可查看商城订单；订单号后展示“下单酒店”，只显示酒店当前名称，不增加地址、联系人或电话。
- 酒店筛选默认全部，候选可按名称搜索，包含停用酒店；选项以酒店唯一标识区分同名酒店。搜索候选不直接改变已查询列表，点击查询后生效。
- 查询及重置回到第一页，每页20条；分页、错误重试保留已生效的酒店条件。重置恢复全部酒店，总条数与当前筛选一致。
- 无匹配订单显示空状态；酒店候选或订单读取失败分别提示并提供重试，快速切换查询时只展示最后一次结果。
- 保持原订单金额、商品快照和状态；酒店端仍只能查看本酒店订单，平台列表只读。
- 列表字段：商城订单号、下单酒店、商品明细、商品件数、订单金额、状态和下单时间。

### 4.12 平台成员

- 成员列表展示：平台成员与工厂成员复用同一表格、筛选栏、操作区和分页布局；平台固定组织，不增加可切换组织筛选。各成员及司机列表的编辑、删除保持清晰间距，避免误触，角色权限不因样式变化而改变。
- 页面范围：系统管理的“平台成员”固定管理优洗通平台所属成员，默认展示该平台全部成员；不提供跨酒店或工厂的组织筛选。姓名或账号、角色、状态条件取交集，重置仍保持平台范围。新增成员的所属组织固定为优洗通平台，角色沿用该组织及操作者允许分配的选项；司机仅归属工厂，不属于优洗通平台。酒店、工厂成员分别从酒店成员、工厂成员管理。

#### 用户、角色与账号维护

- 关系规则：一个账号属于一个组织、具有一个固定角色。组织决定基础数据归属，角色决定业务操作；司机负责酒店属于业务分配，与所属工厂分别展示。无跨组织任职、多个角色、自定义权限或账号迁移；账号与司机删除遵守第 3.7 节保护规则。
- 展示规则：用户列表展示姓名、登录账号、所属组织、组织类型、中文角色、状态和创建时间；账号、组织只读，密码不展示。角色说明展示职责、使用端与数据范围；空的普通文本显示“—”。
- 筛选规则：姓名或账号共用文本搜索，任一字段模糊匹配即命中；角色、状态为可清空单选，默认全部，多个条件取交集；酒店、工厂成员页面另提供本类型组织单选，平台成员页面固定平台组织。角色来自固定角色目录；状态为启用、停用。点击查询或回车生效并回第一页，重置清空全部条件；自动更新保留条件。用户每页默认 20 条，按创建时间倒序，同一时间按账号编号稳定排序；无结果提示调整条件。
- 所属组织：平台成员新增时固定优洗通平台；酒店、工厂成员新增时必填、可按名称搜索选择对应类型组织，仅可向启用组织添加账号；组织列表的独立成员页面入口预填只读。切换组织后清除原角色，再选择该组织及当前操作者允许分配的角色，不保留非法组合。
- 角色选项：平台可选平台管理员、平台运营、平台财务；酒店可选酒店管理员、酒店操作员；洗涤厂可选工厂管理员、工厂操作员、工厂财务。司机仅归属工厂，但仅从司机管理进入包含负责酒店的司机创建流程；酒店不可创建司机。
- 新增字段：姓名、全局唯一登录账号、角色、初始密码和确认密码必填。组织从选择结果取值；登录账号不可与任何存量启用或停用账号重复。新建账号初始为启用；酒店最多 10 个启用账号，包含管理员。
- 司机归属：创建司机必须选择启用工厂，平台及酒店不能作为司机所属组织；平台成员仅展示平台角色，不提供司机创建选项。平台管理员和运营统一在司机管理中按原权限管理司机。存量错误归属须核实实际工厂后处理，不按负责酒店推测归属。
- 司机规则：所属组织仅工厂；首家负责酒店与负责区域必填，酒店从酒店清单中选择。创建账号与首家酒店分配共同成功或失败，不能只建没有负责范围的司机账号。既有司机可修改姓名、启停用或重置密码，不允许转换为其他角色；其他角色也不可直接改为司机。
- 维护入口：列表统一通过“编辑”打开弹窗，“编辑内容”可选“姓名、角色与状态”或“重置密码”。成员页面仅一组筛选：所属酒店或工厂（默认全部、可搜索名称）、姓名或账号关键词、角色及状态；点击查询或回车生效，重置回到全部本类型成员并回第一页。切换组织关闭原操作表单并重新加载，不能把上一组织的成员或迟到结果带入当前组织。
- 姓名维护：预填现值、必填，保存后同步更新相关列表；登录账号和组织不可编辑。
- 角色调整：仅可在同组织内选择合法角色。确认时展示原角色、新角色及职责变化，提示该账号需重新登录。禁止降低自己的管理员角色；禁止把组织最后一个启用管理员改为其他角色。
- 启停用：按当前状态显示停用或启用，停用前确认目标及登录失效影响。禁止停用自己或组织最后一个启用管理员；恢复酒店账号时重新校验 10 人上限，停用账号不占启用名额。
- 重置密码：手工填写新密码与确认密码，沿用统一密码规则；提交前确认将结束该账号现有登录，成功不回显密码，由操作人通过安全渠道告知使用者。新密码不会自动启用停用账号，不提供找回密码、强制首次改密或自动通知。
- 会话规则：停用、角色变化或重置密码成功后，账号原登录全部失效；恢复启用不恢复原登录，需重新登录。仅修改姓名不强制退出。
- 操作反馈：无维护权限隐藏操作按钮；已知的自身或最后管理员限制禁用并显示原因，提交时仍校验最新状态。提交中阻止重复保存；取消不修改资料；失败保留输入并说明冲突原因；成功后自动更新用户及组织成员数据，不再符合筛选的账号从当前结果移除。无批量操作。
- 权限规则：平台管理员可维护全平台账号；平台运营仅可维护非平台角色账号，既不能维护已有平台角色，也不能授予平台角色。平台财务只读。酒店移动端不提供成员查看与创建能力，统一由平台酒店档案维护，本轮不增加工厂自主管理入口。
- 数据保护：最后管理员、酒店名额限制以同一组织最新结果判定，同时操作不能突破约束。账号变更可追溯记录操作者、对象和变更，不记录明文密码。
- 验收标准：建档后可立即查看管理员并继续配人；组织预填和角色联动正确；重复账号、非法角色、越权、名额已满及最后管理员冲突均失败且无部分保存；改角色、停用或改密后原登录失效；财务只能查看；空、加载失败、保存失败都有明确反馈。

## 5. 洗涤厂 Web

### 5.1 经营总览

- 展示待处理订单、备货中订单、待确认退款和工厂应收。
- 数据范围仅限当前洗涤厂。

- 展示规则：一条申请可包含原订单多种布草，逐项展示申请数量、已入库、待入库和最终通过数量；展示申请原因、工厂备注、状态及实际退款。酒店及平台可看酒店金额，工厂不得查看酒店销售价及平台毛利。

#### 6.5.2 购物车

- 底部始终提供可点击的购物车，显示总件数和金额；空车也可打开，显示继续选购引导，确认按钮不可用。
- 购物车逐项展示名称、单价、数量及小计，通过“+ / −”调整数量，通过“删除”移除商品；数量不得小于零，新增数量不得超过库存。原型提供经确认后清空整车。
- 这里管理提交前的已选商品，不修改或删除已支付订单内的商品。
- 返回选购或取消确认保留当前选择；成功后才清空。不同账号、酒店的选择和待确认请求不得混用。
- 价格变化、商品下架或库存不足时明确指出受影响商品，保留选择供用户调整，不静默替换价格后直接提交。

#### 6.5.3 确认、提交与结果

- 购物车主按钮统一为“提交订单”，点击后仍进入确认流程。购物车、确认订单、正在提交和提交成功使用一致的弹窗高度，内容超出时内部滚动。

- 确认页逐项显示商品、数量、小计以及合计，说明从预存账户扣款；可返回购物车修改。
- 提交中展示等待状态，禁止重复提交及修改本次商品、数量。
- 校验酒店启用、商品可售、库存和余额；失败保留所选商品，展示具体原因。校验失败不能产生部分扣款或库存扣减。
- 成功展示订单号，提供“查看订单”和“继续选购”，清空购物车并刷新库存；查看订单打开本单历史明细，返回订单列表选中商城订单。
- 结果尚不明确时，不引导用户另建订单；实际小程序保留原请求，恢复后使用相同商品、数量及提交身份重试，直至确认结果，避免重复扣款。
- 原型模拟提交前后校验和同次提交去重，完整演示确认、失败保留和成功结果。

#### 6.5.4 加载与页面一致性

- 加载、空状态与请求失败分别展示，失败提供重试；错误信息不遮挡底部导航和主操作。
- 商城、布草订单、退污记录及其详情共用清晰的标题、状态、明细、金额和操作层次；长名称、长订单号及大金额换行，不横向溢出。
- 酒店、司机和厂内终端页面统一卡片、文字、按钮与状态颜色；底部导航使用图标和文字，选中态明确，内容避让安全区。
- 弹层内容可滚动，关闭与主要操作易于点击；窄屏、短屏和键盘弹起时能完成操作。视觉调整不改变业务权限、额度、退款或历史价格。

### 6.6 酒店账号维护边界

- 两个酒店角色的小程序均不提供员工账号管理模块、入口或页面；酒店成员由平台有权限人员在酒店档案维护。账号数量、角色与权限约束沿用平台账号管理规则。

### 6.7 个人中心

- 展示用户姓名、所属酒店和当前身份。
- 显示账户与账单和退污记录入口。
- 底部提供独立的“退出登录”按钮；点击直接按第 3.1 节退出并进入业务账号登录页，不使用仅提示退出成功或只切换角色的替代行为。

## 8. 司机微信小程序

- 平台管理员、运营统一在司机管理创建账号和维护负责范围，司机属于工厂，不出现在工厂成员维护入口。

- 新建及启用状态司机至少保留一家负责酒店；账号创建和初始分配共同成功或失败。
- 司机小程序只展示本人负责范围：顶部显示负责区域文字详情，下方按区域分组列出酒店及已有地址；移除区域数、酒店数统计卡片，不增加任务状态或配送确认操作。
- 加载失败可重试；无负责酒店明确显示空状态。越权读取、空区域及重复酒店分配均被阻止。

## 9. 非微信厂内终端

### 9.1 使用边界

- 当前移动端页面仅向工厂操作员开放；工厂管理员通过 Web 查看扫描记录，没有厂内终端的移动入口。事件登记业务授权同时覆盖工厂管理员与工厂操作员，不能将页面入口范围等同于全部业务授权范围。
- 页面采用与微信小程序一致的竖屏移动端比例和单栏操作结构，不使用宽屏侧栏工作台。
- 顶部展示所属洗涤厂和“终端工位”，工作模式在内容区顶部横向切换。
- 微信小程序中不开放厂内终端；进入时提示使用非微信厂内终端并返回登录页。
- 非微信终端提供芯片登记、租赁备货和入库三个工作模式。

#### 使用边界与设备信息

- 厂内终端提供“芯片登记”“租赁备货”“入库”三个标签，入库分日常回收和退污入库；当前为人工登记，硬件尚未接入，不显示扫描成功或在线设备状态。
- 所属工厂只读，站点从本厂权限范围内下拉选择。采集方式只读展示“人工登记（设备未接入）”，没有已配置设备目录时不虚构设备选项、不要求填写设备编号、厂商或协议。后续有真实设备档案时，优先按设备名称下拉选择并展示后台配置资料。
- 资料中的归属公司与规格应由后台统一配置；本期仅展示已存在的归属与品类资料。未确认的规格、设备认证、厂商协议、断网补传均不作为已完成能力。

#### 芯片登记

- 展示并必选有效站点、启用布草品类；芯片号使用必选单选下拉，不允许手动输入；默认提示“请选择演示芯片”，不预选。内置“演示芯片 01 · DEMO-RFID-001”“演示芯片 02 · DEMO-RFID-002”两条信息，按编号升序展示，仅供原型演示，不代表真实硬件读取。数量只读固定为 1，一次记录一个芯片。
- 不选择酒店、订单，不要求操作员填写批次或设备资料。提交记录归属当前工厂与站点，不代表实物已经绑定酒店，也不自动增加酒店可补额度。
- 目前记录登记事件，不具备逐件芯片资产台账、跨批次重复初始化保护或库存生命周期核验。

#### 酒店入库与累计数量

- 厂内操作员新增“入库”标签，内含“日常回收”和“退污入库”；首次芯片登记与租赁备货仍独立保留，微信酒店端不展示厂内能力。
- 日常回收选择本站服务酒店、布草品类、正整数数量，提交后记录酒店归属并恢复该品类额度。非本站服务酒店、无效品类或数量均不可提交。
- 退污入库选择酒店及本厂本站点已确认的退污申请，只能登记申请内品类，展示应入、已入、剩余数量；支持分批，超量和重复批次不重复记账。
- 入库页在选择酒店及品类时展示本厂该酒店品类累计入库（日常回收与退污入库合计），不混放累计出库；租赁备货标签按所选订单的酒店展示本厂各品类累计出库，不混放累计入库。累计出库以成功备货登记为准，不代表第二次额度扣减。
- 工厂只看自身授权形成的累计数量，不泄漏其他工厂明细；酒店总体额度独立保持跨厂连续。首次芯片登记未关联酒店，不计酒店入库或授额。
- 每批退污入库立即恢复对应额度，全部申请数量入齐后自动通过并一次退款。提交中禁用重复操作，结果不明保留同一批次重试；提交失败保留输入且不虚报成功。

#### 订单备货

- 必选本站点已派单或备货中的订单，选项展示订单号、酒店名称；随后从原订单明细下拉选择品类，只填写本次数量，不填写芯片号。展示所选品类计划数量，本次数量必须为正整数。
- 同一订单允许多品类、分批登记。累计有效数量不得超过对应原单计划，跨厂、跨站、非订单品类、配送中及已送达订单均不能新增备货。停用站点或品类仅保留原有待备货订单履约。
- 所有品类备齐后，工厂有权限的人员才能确认出库，再确认送达；登记本身不自动改变订单状态。下单绑定服务工厂和站点，订单保存目标酒店；事件关联订单不等于逐件布草资产已绑定酒店。

#### 批次、反馈与异常

- 批次由系统自动生成并只读展示。首次提交锁定本批内容，失败保留相同内容及批次重试；不确定结果不能靠更换批次重复登记。同厂同批次同内容只记一次，改动内容后不能复用原批次。
- 必填项不完整、无有效候选或提交中禁用提交；错误说明保留，成功更新记录并为下一次登记准备新批次。最近记录展示模式、批次、关联订单（有则展示）、时间、数量及人工登记方式；按时间倒序，空记录显示“暂无登记记录”，失败提供重试。业务凭证不提供删除。
- 当前履约链路为酒店日常入库形成额度、酒店下单、本站点订单备货、出库配送、送达。日常回收与退污入库按酒店和品类登记并恢复额度；硬件自动识别、逐件资产完整追踪仍未实现，不能将人工数量汇总解释为实物库存已核实。

#### 布草分类与选择范围

- 当前已配置布草品类完整清单为：床单、被套、浴巾、方巾、地巾、面巾、内枕套、外枕套，计量单位均为“件”。八类为平级品类，内枕套与外枕套分别选择，不合并为枕套。新增五类不自动获得酒店协议价、工厂成本或酒店额度；配置完成前不得下单。历史订单及价格快照保持原样，运行时以平台实际启用目录及酒店配置为准。
- 当前品类只有名称、单位、图片和启停状态，不按尺寸、材质、颜色、等级建立子分类。归属洗涤厂及站点来自账号和后台档案；规格资料、额外品类需先由业务确认并配置，不能让操作员自由填写或新增，也不能把尚未配置的规格作为可选项。
- 布草品类与易耗品商城种类相互独立；商城种类管理不改变布草目录，不能混用两套候选。

| 使用场景 | 下拉候选与展示规则 |
|---|---|
| 酒店补充下单 | 同时配置当前酒店协议价与当前承接工厂成本价的启用品类；无额度记录按 0 展示，零额度不能提交正数量 |
| 酒店协议价、工厂成本价 | 平台启用的布草品类；价格按所选酒店或工厂分别配置，不从商城种类选取 |
| 酒店额度上限 | 全部启用品类；仅设置上限，不授予可下单量。下单仍须双价格齐备及有效净入库额度 |
| 首次芯片登记 | 平台启用品类；显示名称和单位，操作员不得输入品类编号或自由新增 |
| 订单备货 | 所选本站点待备货订单的原单品类；原单品类后来停用仍可履约，不纳入订单外品类 |
| 退污退款 | 原订单明细及剩余可退数量；沿用历史名称和价格，不改选现行目录其他品类 |
| 工厂仓库 | 汇总当前启用品类，含零事件数量；历史扫描记录保留可追溯，停用品类不因此删除历史事件 |

- 普通品类下拉按名称排序，订单与退款按原单明细顺序展示；切换站点或订单时清空不再适用的选择。空候选显示原因并禁用提交，不用手工文本替代缺失选项。多个筛选条件按交集生效。

## 10. 当前业务规则

### 10.1 可补额度

- 展示规则：酒店档案逐品类展示额度上限和当前可下单量。上限独立设置；当前可下单量只读，零上限有效。
- 交互规则：平台管理员、运营设置额度上限；不设置期初数量，不提供核定入口。没有有效入库时可下单量为零，初始入库50、未下单且上限不少于50时可下单50。
- 数据规则：可下单量＝配置上限与“新增日常回收入库＋新增退污入库－新增下单数量”非负值的较小者。下单数量包含待备货订单，既有订单继续履约，不重复扣减新口径额度。
- 入库超过上限的部分仍完整记录；上限调整不直接授额、不撤销原订单。备货将未备货占用转为累计出库，不再次扣可下单量。所有数量按酒店、品类核算，跨楼层及换厂延续。
- 历史规则：原额度配置只作为上限衔接，不作为初始可下单量。新口径累计量从有效酒店入库及新下单记录形成；无法归属的历史入库不猜测授额，既有订单、资金和历史流水不重放。
- 校验与反馈：数量为非负整数，版本冲突需重读核对；入库与下单并发不能超额，同一提交重试只生效一次。财务只读，不可修改上限。
- 验收：日常入库50、下单40时可下单10；退污入库5后累计入库55、可下单15，仍受上限限制。

### 10.2 补充订单与预存余额

- 酒店管理员和酒店操作员均可提交补充订单。
- 下单至少包含一个大于零的布草品类数量。有启用楼层时必须选择所属酒店的有效楼层；无启用楼层时允许不指定楼层。
- 每个品类必须同时存在酒店协议价和承接工厂成本价。
- 酒店必须启用且配置有效承接工厂与站点，工厂及站点也须启用；未配置承接工厂时无选品候选，关系无效时不能下单。
- 下单金额为各品类数量乘以酒店协议单价后求和。
- 账户余额不足时不生成订单、不扣额度、不扣余额。
- 成功下单时，订单创建、额度扣减和余额扣减作为同一次业务处理完成。
- 同一提交标识重复提交相同内容时返回原订单，不重复扣款；提交不同内容时拒绝。

### 10.3 订单履约

- 新订单在服务关系有效时直接进入已派单状态。
- 只有待派单异常订单可由平台管理员或平台运营重新指定工厂和站点。
- 工厂履约状态必须依次从已派单进入备货中、配送中和已送达；所有订单品类累计备齐后才能出库，缺少任一品类均拒绝进入配送中。配送中及已送达后不得追加备货，重复提交既有相同批次不重复计数。
- 工厂管理员和工厂操作员可更新状态；工厂财务只读。

### 10.4 退污与退款

- 展示规则：一条申请可包含原订单多种布草，逐项展示申请数量、已入库、待入库和最终通过数量；展示申请原因、工厂备注、状态及实际退款。酒店及平台可看酒店金额，工厂不得查看酒店销售价及平台毛利。
- 申请规则：首次送达后24小时内可提交，到达截止时刻即关闭；以系统判定为准。每单只能成功提交一次，驳回也占用机会；网络重试返回原申请，不新增次数。缺少可靠送达时间的旧单不开放新申请。
- 提交规则：从订单列表或详情进入，选择本单一个或多个品类，数量为正整数且不超过原明细数量，整单原因必填。提交中防重，失败保留输入；提交成功返回退污记录，原订单“已送达”旁显示“有退污”。
- 工厂确认：待确认申请只能整单同意或整单驳回，不可调整任何品类数量；驳回须说明原因。整单同意后进入待入库，此时不退款、不扣结算、不增加额度。
- 入库规则：操作员在退污入库选择已确认申请，按申请明细分批登记，不超过剩余待入库数量。每批入库立即恢复对应品类额度；全部明细入齐后申请自动通过，并一次退款及扣减工厂结算。
- 金额规则：退款按入齐数量乘原酒店销售单价；工厂扣减按同数量乘原工厂成本单价，沿用历史快照。多品类、多批次只计一次整单入账，失败不留下部分资金变动。
- 历史规则：既有申请按原审核方式继续处理，历史部分通过数量与金额准确保留，不生成额外退款。新流程不支持撤回、修改已确认数量或强制结束部分入库。
- 筛选规则：平台和工厂按酒店、布草、状态交集查询，默认全部，状态包含待确认、待入库、已通过、已驳回；历史停用品类可查。酒店只看本酒店记录；查询返回第一页，失败可重试。
- 验收：两品类一次提交、24小时边界、并发一次限制、驳回不能重提、分批入库即时增额度、最后一批一次退款及原成本扣减均保持一致。

### 10.5 商城订单

- 酒店管理员和酒店操作员均可下单。
- 商品必须处于可售状态，购买数量不能超过当前库存。
- 商城金额按商品统一售价乘以数量求和。
- 酒店预存余额不足时不生成商城订单。
- 成功提交时，商城订单创建、库存扣减和余额扣减作为同一次业务处理完成。
- 同一提交标识不得产生重复订单或重复扣款。

### 10.6 价格与结算口径

- 酒店协议价与工厂协议价分别在所属管理模块展示。
- 酒店订单与小程序只使用酒店协议价。
- 工厂订单与结算只使用工厂成本价。当前成本按洗涤厂和品类配置，同厂各站点共用；是否按站点独立定价待确认，本期不改变既有价格。
- 平台订单同时展示酒店原额、已退金额、酒店净支付、工厂原应付、退污扣减、工厂净应付及平台净毛利。
- 工厂结算只汇总已送达订单的原工厂成本、已通过退污成本扣减及工厂净应付。

## 11. 当前验收标准

### 11.1 角色与导航

- 每个测试账号登录后进入与其角色匹配的首个页面。
- Web 菜单与本文权限矩阵一致。
- Web 右上角展示组织、角色和用户姓名，用户菜单可执行退出登录。
- 酒店“我的”页与司机工作台退出均无需二次确认，退出后展示空账号、空密码的业务账号登录页且没有酒店底部导航；返回不恢复已退出工作台，注销失败也清除本机身份。重新登录按实际账号角色进入工作台。
- 酒店与工厂账号不能查看其他组织的数据。
- 酒店、工厂建档均配置首个管理员，失败无部分保存；工厂不填写首站点和地址，不自动建站；档案列表通过“成员”进入独立成员页面并预选组织，添加成员打开独立表单，“详情”只读，“编辑”独立表单，用户列表按条件交集查询。
- 平台运营不能维护原有平台角色或授予平台角色；财务只读；最后管理员、自己停用、酒店启用名额限制不可绕过。
- 改角色、停用和重置密码后原登录失效，组织成员与用户列表保持一致。
- 工厂订单不显示酒店扣款和平台毛利。

### 11.2 补充订单

- 酒店建档不出现楼层及酒店站点名称；无楼层可浏览、下单、查询及重复提交。
- 添加楼层后出现切换，切换保留品类数量，价格和额度不变；刷新保留有效选择。
- 楼层排序、单条添加重名、停用恢复、提交前停用及跨酒店归属校验正确；无楼层统一显示“未指定”。
- 加减数量不能突破零和该品类可补数量。
- 金额与件数随数量变化正确更新。
- 额度不足、余额不足、价格缺失或酒店服务关系缺失时不生成订单。
- 成功下单仅生成一笔订单、一次额度扣减和一次余额扣减。
- 重复提交相同内容不会重复扣款。

### 11.3 履约与退款

- 工厂订单只能按既定顺序推进至已送达。
- 工厂财务不能更新订单状态。
- 酒店只能对已送达订单的剩余可退数量发起退污。
- 新申请只能整单确认或驳回，不能调整品类数量；历史申请保留原部分审核。
- 驳回必须填写原因且不改变酒店余额。
- 新申请全部退污入库后自动通过并一次退款；每批入库恢复额度，首次工厂确认不改变金额。

### 11.4 账户与商城

- 酒店管理员按元申请充值，平台管理员和平台财务直接登记充值或审批酒店申请；12.34 元申请不入账，通过审批后余额恰增 12.34 元，银行号保留前导零及分隔符，跨酒店同银行号不可重复入账，已审批申请不可改判。
- 酒店管理员可查看资金流水；酒店操作员进入该入口时收到无权限提示。
- 商品种类必选，种类管理与商品选择同步；图片通过本地文件选择并可预览、更换、移除；未选择图片时使用占位图。商城提交时再次校验库存和余额。
- 商城采用双列商品卡，字段与第 6.5 节一致；零选择保留购物车入口并禁用确认，取消确认保留选择，提交失败保留选择；成功显示订单号并清空选择、刷新库存。
- 商城成功下单仅生成一笔订单、一次库存扣减和一次余额扣减；提供商城历史订单与订单详情，不提供独立商品详情；购物车支持调整提交前的商品。

### 11.5 工厂数据与终端

- 仓库页面按事件汇总累计入库、累计备货和当前可用数量，不能解释为逐件实物库存已核实；终端分批、多品类备货正确累计，缺任一品类均不能出库。
- 工厂财务不显示仓库、扫描和退污菜单；所有工厂角色均不显示工厂结算菜单，旧页面进入后返回经营总览。
- 厂内终端以竖屏移动端比例展示，工作模式、事件表单和最近事件按单栏顺序排列。
- 只有工厂操作员账号拥有厂内终端移动页面入口；此入口规则不改变已有的工厂管理员事件登记业务授权。
- 微信小程序不允许进入厂内终端。
- 厂内终端的芯片登记在未选择内置演示芯片时不能提交，数量固定为 1。
- 同厂相同采集事件编号重复提交相同事件不会生成重复记录；改订单、品类或数量后复用编号须拒绝。跨厂、跨站、非订单品类、超量备货和出库后追加均拒绝。

### 11.6 页面状态

- 关键页面具备加载、空数据、错误重试和无权限状态。
- 列表筛选、自动加载和分页可正常使用，页面不出现独立刷新按钮，失败重试保留。
- 翻页适用于本文列明的 Web 分页列表及酒店移动端充值申请、资金流水列表；其他移动端最近 20 条列表不验收为全量历史检索。
- 关键提交操作具有禁用、确认、成功和失败反馈。

### 11.7 酒店、楼层和服务关系

- 酒店下拉选择、状态、关联站点筛选取交集，包含待配置酒店；酒店和洗涤厂统一从对应的酒店或工厂档案建档，维护模块只能选择已有组织；楼层单条添加，允许删除无订单引用的误建楼层；有订单引用时拒绝删除。
- 工厂多站点和站点服务酒店完整展示；工厂与站点名称联动，更换工厂清空旧站点。
- 关系配置、更换及解绑成功后，酒店列表和再次打开的只读详情保持一致，仅影响新订单；没有关系时提示配置承接站点，不提供补充选品候选且不能下单。
- 酒店、工厂和站点停用不阻断旧订单履约、查询及退款；有服务酒店的工厂和站点不能直接停用，恢复不重建解除的关系。
- 同时编辑发生冲突时不能覆盖他人结果；新下单使用提交时有效的楼层、状态及关系，不出现部分成功。
- 新订单名称、酒店地址与价格保留原记录；改名、改址及服务关系变更不改写既有订单。
- 财务仅能查看酒店、楼层、工厂站点与服务关系；终端只选择本厂站点，停用站点仅用于已有订单允许的租赁备货。

### 11.8 详情、成员与编辑入口

- 对应的酒店或工厂档案列表分别打开只读详情、独立成员页面和独立编辑表单；关闭后保留列表筛选，取消编辑不保存，成员操作不改变组织资料。
- 组织详情仅展示组织资料，不含成员列表、新增成员或编辑按钮；成员权限、最后管理员与删除保护沿用原规则。
- “酒店档案”列表独立提供详情、楼层、额度、更换、解绑、删除；未配置时显示配置且无解绑。详情只读酒店信息、楼层信息、承接工厂与站点；详情不含维护按钮。酒店资料编辑统一在对应的酒店或工厂档案完成。
- 工厂基本信息及类似单对象详情使用描述卡，多条站点、楼层和成员明细仍保留列表或表格。

- 工厂档案提供新建工厂、只读详情、独立资料编辑、成员及站点管理入口；低频删除归入“更多”，沿用引用保护和独立确认。站点管理固定工厂，站点删除仍在站点管理内执行。

### 页面加载、种类弹窗与金额统一规则

- 所有页面不提供独立“刷新”按钮。进入页面自动加载，保存、删除、充值等业务提交成功后自动更新相关列表、详情、余额及统计，保留适用的筛选与页码；查询、重置、分页以及读取失败后的重试仍可使用，不要求用户为看到提交结果手动刷新。
- 种类管理列表与新增种类表单分开：管理弹窗显示列表、删除及新增入口，新增入口打开独立名称表单。提交中禁止重复操作，取消不新增；成功返回管理列表并自动更新候选，失败保留输入，原有种类引用保护不变。
- 所有价格及金额输入以人民币元为单位，最多两位小数，包括酒店协议价、工厂成本价、商城售价和充值到账金额；酒店协议价和工厂成本价允许 0，商城售价及到账金额必须大于 0。拒绝负数、超两位小数和非金额内容，不静默四舍五入；列表、详情与统计均以元显示两位小数。
- 平台“钱包与流水”展示所选酒店余额、充值申请、关联业务 ID、银行流水号和审批状态，只有平台管理员、平台财务可查看、登记直接充值并审批酒店申请；平台运营不显示该模块和登记审批入口，不因其他资料维护权限取得资金权限。
- 酒店管理员可在本酒店账户提交线下充值申请，查看余额、申请审批结果、关联业务及资金流水；申请不等同入账，不提供在线支付成功流程。酒店操作员继续沿用既有补充页余额展示权限，不取得账户流水权限。
- 验收：协议价 0.00 元可保存，商品价与充值 0.00 元被拒绝；12.34 元输入、列表和余额变化一致；超两位小数不被舍入接受。财务或管理员审批通过后自动更新钱包及对应流水，银行号前导零与分隔符保留；运营无资金入口。各页面无独立刷新按钮，查询及失败重试仍有效。
