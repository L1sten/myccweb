# 优洗通当前系统开发交接说明

## 1. 材料与演示边界

- 本套材料包含 PRD.md、index.html、app.js、styles.css，以及本说明的 Markdown 和 HTML。前端、后端、测试共同使用；PRD 只描述业务规则，工程契约与验证限制记录在本说明。
- 本套原型同步 fullstack 的商城、布草归属、备货出库、建档和受保护删除，并更新 2026-09-14 充值申请、银行流水绑定与审批链路。
- 原型使用浏览器内的示例数据和本地交互状态，不调用生产服务。图片选择只演示本地预览、更换和移除，不表示文件已上传服务器；充值、下单、退款、删除和备货成功提示均不表示真实资金、实物或生产数据已变化。
- 静态原型的角色选择、页面状态选择和 PRD 分栏属于评审工具，不是生产登录或权限配置。静态页面访问保护也不等同业务鉴权，不得存入真实客户资料或密码。
- 本轮属于本地项目与静态原型材料同步及原型发布，不部署正式服务，不执行运行数据库迁移。发布记录与版本记录由正式发布流程独立维护。

## 2. 使用端、角色与组织边界

- 平台 Web：平台管理员、平台运营、平台财务。经营总览仅管理员和财务可见；线下充值申请仅管理员和财务可登记与审批；运营不能维护或删除平台权限账号。
- 工厂 Web：工厂管理员和操作员可推进本厂履约、确认退污；工厂财务只读查看经营、订单与报表；所有工厂角色不显示工厂结算模块，残留页面进入后返回经营总览。平台工厂结算模块、工厂订单结算金额和业务报表保留，不提供资金或原始业务记录删除。
- 微信小程序：酒店管理员、酒店操作员、司机。酒店管理员和操作员均可查看补充页精确余额、补充下单、申请退污和商城下单；流水与员工页面仅酒店管理员可进入。
- 司机一期只读查看本人负责区域、酒店、地址和服务点，没有任务、定位、导航或签收操作。
- 非微信厂内终端：移动入口仅工厂操作员可进入；后端终端业务同时授权工厂管理员和工厂操作员。不得把入口范围当作服务端授权边界，亦不据此扩展管理员移动入口。微信构建不开放终端。
- 一个账号属于一个组织并具有一个角色。所有组织隔离与业务授权由后端再次校验；客户端隐藏、下拉候选和本地校验均不能替代后端验证。


### 酒店可补额度设置与双价格选品

- 酒店选品的候选由启用 SKU、当前酒店协议价、当前承接工厂成本价共同决定。额度改为可缺省来源，无额度记录返回 0，不再因没有额度行隐藏已配置双价格的 SKU；零价等同已配置，零额度仍禁止正数量下单。
- 管理端复用“酒店与站点”列表独立额度弹窗，平台管理员和运营设置目标可补整数（≥0），平台财务只读。额度弹窗只列本酒店与当前承接工厂双价格配齐的启用品类；页面展示当前值和目标值，点击保存校验后直接生效，不展示差额确认页面或二次确认弹窗；不能将目标值当作增量直接累加。
- 额度以酒店+SKU 为作用域，不因工厂、站点或楼层变化建立副本。差额追加额度流水与审计，历史流水和订单保持不变；不改变资金存储单位。部署前执行 v7 酒店额度调整幂等迁移，持久保存调整请求与成功响应；额度、流水和请求记录同事务提交，存量数据卷不会随镜像升级自动迁移。
- 契约：`GET /api/admin/hotels/{hotelId}/quotas` 返回数组，各项为 `sku_id/sku_name/unit/credited_quantity/consumed_quantity/available_quantity/version`；缺额度行时数量及版本为 0。`POST` 同路径接收 `sku_id/target_quantity/version/idempotency_key`，返回调整后的单项。界面不填写或提交调整原因，`reason` 仅作为可选兼容字段保留。目标数量 0–2147483647；累计额度还须能容纳已用量与目标量之和。
- 读取与提交校验版本，遇并发订单扣减或人工调整冲突时重读当前值，由用户核对目标值后重新点击保存，不自动重试覆盖；同一次操作以同幂等标识和同内容重试，不能重复记账。后端最终校验权限、酒店/品类归属、整数范围与版本，前端状态不可代替服务端保护。
- 原型价格、额度和酒店补货共用当前演示数据，价格维护、额度设置与下单后自动联动；原型成功不代表真实资金或生产额度变化。
- 资金与额度变更合并或发布前须双人人工审查及后端集成测试；覆盖无额度行可见、单价缺失、零价、目标增减、无变化、冲突重读、幂等及并发扣减，不沿用历史测试通过记录证明本轮结果。

### 厂内终端与布草目录

- 操作界面统一为“芯片登记”“订单备货”。前者选择站点、启用品类、下拉选择内置演示芯片且数量固定 1；后者选择本站 `DISPATCHED/PREPARING` 订单及原订单 SKU、输入正整数数量，不展示芯片输入。模式仍对应 `CHIP_INBOUND` / `RENTAL_STOCKING`，不修改事件业务含义。
- `business_reference` 由客户端自动产生、只读展示；失败冻结原 payload 和批次重试，避免网络结果不明时另建批次导致重复。与 `order_id` 分离；同批次变更内容由服务端拒绝。原型芯片号禁止手输，仅提供 DEMO-RFID-001、DEMO-RFID-002 两条演示选项，不代表真实设备数据。
- 当前采集方式 `MANUAL` 只代表人工登记；没有设备注册目录或厂商协议，不伪造设备列表、连通状态或扫描结果。设备信息优先复用后台配置并以名称选择，当前仅只读说明未接入；不得开放手填设备号替代设备接入。
- `linen_sku` 现有字段为 `id/name/unit/image_url/active`。初始目录为床单、被套、浴巾、方巾、地巾、面巾、内枕套、外枕套，单位均“件”；v6迁移仅补新增五类，重复执行保留已有编号、同名资料和停用状态，不生成价格或额度；无尺寸、材质、颜色、等级字段。额外品类与规格须业务确认后统一配置；操作员不能自由新增。商城 `store_category` 与布草目录独立。
- 酒店候选采用同时配置当前酒店协议价、当前承接工厂成本价的启用 SKU，无额度记录按 0 返回；价格配置选启用 SKU；额度配置只列双价格配齐的启用 SKU；首次登记选启用 SKU；备货和退款保留原单历史 SKU 范围。`factory/warehouse` 仅返回启用 SKU 的事件汇总（含零数量），停用不删除历史扫描事件。
- 归属工厂由登录组织确定，站点由本厂候选选择。事件记录关联站点及订单，不替代逐件资产绑定酒店；未实现跨批次芯片去重、实物库存生命周期、脏布草回收扫描、洗涤入库与自动授额闭环。
- 验收覆盖：必填和数量边界、切换站点/订单清空无效选项、历史停用 SKU 履约、跨站及超量拒绝、失败原批重试、人工设备提示、无候选不可提交。质量门禁结果以本次实际检查为准，不沿用历史检查数量证明本轮通过。

## 3. 酒店、工厂与布草的真实模型

- 酒店与洗涤厂统一在“客户与组织”建档。酒店填写名称、区域、地址和首个管理员，不创建默认楼层；工厂仅填写名称和首个管理员，不要求或自动创建首站点、区域或地址。
- 工厂建档后可暂时没有站点，站点从工厂列表“站点”入口的独立管理弹窗新增。新增站点填写名称、区域和地址；配置启用站点及酒店服务关系后才能承接新单。工厂原建档请求中的站点字段为兼容旧请求保留，已不用于生成站点。
- 酒店楼层为轻量归属信息，按名称、顺序、状态维护；每次新增一条，同酒店名称唯一。无启用楼层可无楼层下单；有启用楼层时必须选择，切换仅改变本次订单归属，不清空已选数量。
- 布草 SKU 为平台共享品类。酒店价格按“酒店＋SKU”，工厂成本按“洗涤厂＋SKU”，同厂各站点共用成本。是否改为站点独立成本仍待业务确认；本轮没有迁移价格或重算历史资金。
- 服务关系为“酒店 → 承接洗涤厂＋具体工厂站点”。一个工厂可有多个站点，一个站点可服务多个酒店，一家酒店当前最多关联一个承接站点；更换工厂必须清空旧站点。
- “酒店与站点”“洗涤厂与站点”维护模块只选择既有档案；组织资料与成员在“客户与组织”维护，列表分别提供“详情”“成员”“编辑”：详情只读描述卡，成员独立弹窗，编辑独立表单。工厂列表“详情”以描述卡和只读列表展示工厂及站点信息，“站点”独立弹窗维护站点；“酒店与站点”列表分别进入只读详情、独立楼层管理、配置或更换选择、解绑确认及受保护删除确认；详情展示酒店、楼层及承接工厂/站点，不含维护按钮，不重建独立服务关系菜单。
- 逐件 RFID 布草资产、芯片唯一性、重复初始化保护、酒店实物绑定或换绑以及脏布草扫描自动授额尚未形成完整闭环。不能将选择品类或登记备货理解为逐件布草已经绑定站点或酒店。

## 4. 下单、备货、出库与交付

- 酒店提交补充订单时校验有效楼层、酒店协议价、工厂成本、启用承接关系、品类额度与预存余额。订单创建、额度扣减和余额扣减整体成功或失败，正常新单直接进入 DISPATCHED（已派单／待备货）。
- 订单保存工厂、站点、酒店地址、名称及价格快照。后续更名、停用、解除或变更服务关系仅影响新订单，不重分配旧单、不重算历史价格。
- 终端租赁备货先选择本站点待备货订单，再选择订单品类。`order_id` 表示关联订单，`business_reference` 是独立采集批次幂等编号；同订单可多个 SKU、多批次采集，不再将二者混为同一字段。
- 后端锁定订单并核对所属工厂、站点、状态、品类与累计数量。跨厂、跨站、非订单品类、超计划数量及出库后追加均拒绝。同厂同批次同内容重试返回原事件，改变内容复用编号拒绝；编号保留前导零，仅裁剪首尾空白。
- 工厂履约依次为 DISPATCHED → PREPARING → OUTBOUND → DELIVERED。进入 OUTBOUND 前，每一个订单 SKU 的累计有效备货数量必须等于计划数量，缺任何一个品类均拒绝出库；司机不承担送达确认。
- 已停用工厂或站点不接新业务，但允许其原有待备货订单继续履约；订单品类之后停用也不阻断原单备货。首次芯片入库仍要求启用品类及有效站点。已成功采集的相同批次在出库后重试不重复计数，新增批次不允许。
- 终端事件不自动推进订单状态、不自动授予酒店额度。工厂仓库仍按首次入库与租赁备货事件汇总：累计入库减累计备货可能为负，当前没有逐件实物库存不足拦截；出库数量门禁不等于实物库存闭环。
- 酒店仅对已送达订单的一条明细申请退污。工厂可全额、部分同意或驳回；按确认数量和原酒店成交价一次退款至预存余额，不恢复布草额度。

## 5. 商城种类与图片

- 商品种类在“种类管理”维护，新增名称不能为空、不能重名且最多 80 字；种类按名称排序。商品新增种类必填，使用可搜索下拉，只能选择现有种类，不接受自由文本代替选择。
- 种类使用 `GET /api/store/categories` 查询，平台管理员和运营通过 `POST /api/admin/store/categories` 新增、`POST /api/admin/store/categories/delete` 删除。创建商品沿用 `category_name`，但服务端验证其存在。
- 商品图片选填，选择 PNG 或 JPEG 文件，支持预览、更换和移除，不再输入图片 URL。正式上传 `POST /api/admin/store/images` 接收 multipart 文件，服务端识别真实内容，限制 1MB、宽高不超过 2048 像素，重编码为 PNG 并生成随机文件名。
- 原型仅在浏览器本地读取文件展示预览；真实项目返回 `/media/store/{uuid}.png`，上传要求鉴权。图片处理或上传中阻止商品保存；失败保留既有图片与其他输入，未上传使用占位图。
- 正式项目使用 `PRODUCT_IMAGE_DIRECTORY` 配置持久目录、Compose 的 `product-images` 卷及 Nginx/Vite 图片代理。小程序从合法 HTTPS API 源推导图片域名，并需配置合法下载域名；原型预览不验证这些部署条件。
- 商品名称、说明、售价和初始库存仍按现有业务校验；商品售价输入与列表均以元展示，最多两位小数且须大于零。当前没有上下架、补库存、物流、签收或售后功能。
- 商品无商城订单引用时可删除；已被商品使用的种类不可删除。种类管理与商品删除均有确认、提交中状态和失败原因。
- 商城下单继续原子校验商品、库存和酒店余额，生成订单、扣库存与扣余额，重复提交不重复扣减；当前订单创建后为已支付，不代表存在物流闭环。

## 6. 钱包、充值申请与审批流水

- 原型演示酒店管理员提交线下充值申请 → Web 平台管理员或财务绑定银行流水审批 → 通过后更新演示余额及账本。提交和驳回不入账，不提供微信支付。
- 金额以元输入，大于零且最多两位小数，12.34 元精确转换为 1234 分；拒绝超精度而非静默舍入。真实服务继续使用整数分。
- 原型仅在浏览器中模拟申请、审批、防重与余额变化；生产幂等、事务与银行号唯一性由后端保障。静态原型发布不等同真实资金部署或完成生产审查。

### 角色与状态

酒店管理员提交和分页查询本酒店申请；平台管理员、平台财务按酒店与审批状态查询并审批。酒店操作员、运营、司机、工厂角色不取得充值申请或审批权限。状态为 `PENDING → APPROVED / REJECTED`；通过时同一事务写入钱包、唯一账本及审批结果，驳回不入账，终态不允许改判。

### 接口与关联字段

- `POST /api/hotel/wallet/recharges`：`amount_cents`、可选 `description`、`idempotency_key`；`external_reference` 为可选兼容字段，酒店表单不再要求填写或提交付款参考号。提交返回待审批记录；相同幂等键与相同内容重试返回原申请，内容冲突拒绝。
- `GET /api/hotel/wallet/recharges`：按当前酒店隔离，支持 `limit/offset` 分页。
- `GET /api/admin/wallet/recharges`：`hotel_org_id`、`approval_status` 与 `limit/offset`；审批状态支持 `PENDING/APPROVED/REJECTED`，不传表示全部。
- `GET /api/admin/wallet?hotel_org_id=...`：独立查询所选酒店当前余额，不从分页流水推断余额。
- `POST /api/admin/wallet/recharges`：平台登记待审批申请，新客户端提交 `hotel_org_id`、`amount_cents`、可选 `description` 与显式 `idempotency_key`，不再填写或提交付款参考号；旧 `external_reference` 仅用于兼容回退防重，**不再直接入账**。旧客户端必须随本次后端更新同步升级，不可把成功响应提示为到账。
- `POST /api/admin/wallet/recharges/{id}/review`：`approved`、`external_reference`（通过时必填的核验银行流水号）、`note`（驳回时必填的原因）。同一核验银行流水不得跨申请或跨酒店重复入账。
- 充值记录返回 `id`（充值业务 ID）、`hotel_org_id`、`amount_cents`、`payment_reference`（历史原始付款参考号，仅后台兼容保留，不在两端表单、列表或详情展示）、`external_reference`（核验银行流水号）、`description`、`approval_status`、`wallet_entry_id`、`review_note`、`created_at`、`reviewed_at`。待审批及驳回无入账流水 ID，不以申请 ID 冒充账本 ID。
- 钱包流水补充 `business_id`、`external_reference`、`approval_status`，通过 `wallet_entry_id` 对应实际账本 `id`；原 `business_key` 仅在后台保留，用于内部关联和防重复入账；入账流水 ID、业务关联键及历史付款参考号均只在后台保留，不在 Web 与小程序界面展示。历史流水没有审批记录时关联业务 ID 和审批状态为空，页面明确展示历史未审批，不猜测或回填审批人。

### 手机账户展示

- 余额卡下直接展示金额、可选备注与提交按钮，不再打开申请弹窗。记录列表以中文状态或业务类型、金额和时间紧凑展示，点击展开业务 ID、银行号、备注及审批说明。待审批和驳回申请可查；已通过申请与已加载的对应入账流水合并展示，尚未加载对应流水时保留已入账摘要；未入账申请不能套用钱包余额伪造变动后余额。Web 申请只选择酒店、填写金额与可选备注，两端均不输入或展示付款参考号；历史值仅后台兼容保留。审批通过仍必须核验并绑定银行流水号。账户记录按发生或申请时间合并倒序，整体无记录时显示“暂无账户流水”；实际客户端两类记录各按 20 条分页获取，静态原型合并后按每页 20 条展示。

### 联调验收

1. 酒店申请 12.34 元，得到业务 ID 和待审批状态，余额、账本均不变。
2. 财务核验并绑定带前导零和分隔符的银行流水号，通过后余额只增加 1234 分，申请与流水互相关联，两端一致。
3. 拒绝申请必须填写原因，状态变为已驳回且不入账；终态不能改判。
4. 验证网络重试、并发审批、同银行号跨申请及跨酒店操作均不重复入账；非法角色和跨酒店查询被拒绝。
5. 申请成功及审批成功后自动更新相关列表和余额；失败保留输入，支持重试；分页不会把旧账本余额当作当前余额。
6. 新增迁移保留原有账本，历史银行号不得被新审批再次核销；有申请记录的酒店与相关账号不得当作空资料删除。

资金变更仍须在合并或发布前完成双人人工审查；本地集成测试和智能体核验不替代该门禁。

### 正式系统边界

- 正式服务升级需应用 v8 充值申请审批迁移并完成双人人工资金审查与后端集成测试；本次静态原型更新不执行迁移。运行系统既有测试记录见 fullstack 开发交接文档，不能作为本轮原型验收结果。

## 7. 基础资料删除与历史保护

- 删除用于清理误建且无引用的基础资料，覆盖组织、酒店、工厂、站点、楼层、账号、司机、商品与种类；仅平台管理员和平台运营可操作，运营不得删除平台权限账号。逐条确认，不提供批量删除。
- 组织有业务订单、资金流水、额度、协议价格、服务关系、扫描记录、非零余额，或成员有会话、历史业务及操作记录时拒绝删除。无业务空组织可连同无业务成员、楼层、地址和零余额空钱包清理，创建与删除审计保留。
- 楼层有订单引用不可删除；工厂站点有服务关系、订单或扫描事件不可删除，酒店地址不允许作为独立工厂站点删除。状态停用不自动解除历史引用。
- 账号有会话、业务或审计历史不可删除，当前登录账号、平台组织及最后一个启用管理员受保护。司机按账号规则校验，删除成功同时清理负责酒店分配。
- 商品已有关联商城订单不可删除；种类已被商品使用不可删除。正式商品删除使用 `DELETE /api/admin/store/products/{id}`，其余基础资源通过受保护删除服务校验，不能直接删表或仅依赖前端禁用按钮。
- 订单、退款、钱包账本、审计及扫描凭证保留；库存、结算和报表是汇总，不提供删除汇总行。协议价格继续调价维护。基础资料存在历史时使用适用的停用操作，不把“列表增加删除”解释为删除全部业务凭证。
- 原型只能按示例状态演示“可删、保护阻止、确认取消、成功刷新”；数据库引用约束、并发校验与审计不能用原型本地行为替代验证。

## 8. 账号与密码规则

- 酒店和工厂建档必须配置首个管理员；组织列表的独立成员弹窗添加成员时固定组织，用户列表按名称、角色、状态和组织查询分页。一个账号一个组织一个角色，不支持组织迁移或角色多选。
- 平台管理员维护全部账号，平台运营仅维护非平台角色，财务只读。不得停用自己或降级自己的管理员角色；最后启用管理员不能降级、停用或删除；酒店最多 10 个启用账号。
- 司机属于平台或工厂，创建时同时配置负责酒店，不允许普通用户创建绕过分配，也不允许司机与其他角色互转。移动酒店管理员当前只查看或新增员工，不增加移动删除入口。
- 新账号与重置密码统一手填密码和确认密码，8～20 位，英文字母、数字、英文半角特殊字符至少两类，不允许任何位置有空格、中文、全角字符、换行或表情；密码不裁剪。大小写字母同属一类。
- 确认密码仅在客户端校验，不发送或保存；后端独立校验并 BCrypt 哈希保存。失败保留输入，成功或关闭清空密码；停用、角色变更或改密后原会话失效，恢复不复活旧会话，不自动启用停用账号。

### 酒店列表操作分离与验收

- 列表显示独立“详情、楼层、额度、更换、解绑、删除”；没有服务关系时改为“详情、楼层、额度、配置、删除”，不显示解绑。财务只读，操作权限及删除保护不因入口分离而扩大。
- 详情只读酒店资料、楼层信息和承接工厂/站点；单对象资料使用描述卡，楼层使用只读明细列表。详情中不得出现编辑酒店、管理成员、管理楼层、更换、解绑或删除按钮。
- 楼层和额度各使用独立管理弹窗；配置和更换使用独立工厂/站点选择弹窗；解绑使用单独影响确认；删除使用独立引用保护确认。不能用同一详情容器切换管理模式代替独立入口。
- 配置、更换及解绑只影响新订单；解绑后改显配置，旧单保留快照。删除必须再次校验业务引用，不自动解绑、清空余额或删除历史凭证以绕过保护。
- 验收分别点击各类入口，检查内容互不混入；取消无变化，提交防重、失败保留输入或数据，成功刷新列表与再次打开的详情，关闭保留筛选。本轮复用既有业务契约，不通过文档同步宣称代码测试已完成。

### 工厂详情与站点入口分离

- “洗涤厂与站点”操作列分别提供“详情”“站点”，打开两个独立弹窗。详情只读展示工厂描述卡与站点明细，不嵌入新增、编辑、停用或删除；站点管理弹窗固定所选工厂，保留站点原有维护与引用保护删除。
- 本模块工厂操作列不提供工厂删除；工厂删除统一使用“客户与组织”的受保护删除，避免重复入口。此调整不移除站点删除，也不扩大删除权限或减少历史引用校验。
- 验收详情无写操作、站点管理独立、取消返回原列表；站点新增和删除后刷新列表及后续只读详情，财务没有写权限，工厂删除只能在“客户与组织”发起。

### 金额输入、充值展示与自动更新

- Web 与原型所有金额输入统一为元，包括酒店协议价、工厂成本、商城售价和充值金额；最多两位小数，协议价/成本允许零，商品价/充值严格大于零。客户端须精确转换为现有整数分字段，后端金额存储、计算和幂等约束不变；12.34 元提交为 1234 分，不能以二进制浮点误差或自动舍入放过超精度输入。
- 平台钱包模块只有管理员、财务进入并登记申请、审批，显示所选酒店余额、申请、资金流水、业务 ID、审批状态与银行号；运营无资金权限。酒店管理员可提交本酒店申请并查看审批结果及关联流水，银行号保留前导零与分隔符；酒店端无财务审批能力，原型本地变化不代表真实充值或支付。
- 种类管理弹窗只展示列表、删除及新增入口；新增入口打开独立表单弹窗。成功自动更新列表与商品种类候选，失败保留输入，取消不新增，引用删除保护保持不变。
- 所有页面去掉独立刷新按钮，进入时自动加载，业务提交成功后自动更新关联列表、详情、余额与统计。查询、重置、分页和失败后的重试保留；不能把删除刷新按钮误做成删除数据加载或保存后同步。
- 保留酒店详情/楼层/配置或更换/解绑/删除、工厂详情/站点、组织详情/成员/编辑的既有独立入口，不把新增表单重新塞回只读详情或管理列表。
- 验收覆盖权限矩阵、12.34 元转 1234 分、零值边界、超精度拒绝、银行号原样展示、同号重复与冲突、成功自动更新、独立新增种类与取消返回；本段不代表本轮代码质量门禁已运行，实际结果由主任务汇总。

### 商城商品编辑

- 平台管理员和运营可在商品行点击“编辑”，回填名称、种类、说明、图片和售价；当前库存只读。支持零库存、有订单引用的商品编辑，保留原商品编号与状态。
- `PUT /api/admin/store/products/{id}` 更新商品资料，复用新增的名称、种类、说明、图片和金额校验；库存不在更新请求内，不覆盖下单扣减。权限由服务端校验。
- 保存成功更新列表，取消不修改；校验或网络失败保留输入，保存期间禁止重复提交。图片可保留、更换或移除。
- 酒店商城后续获取新资料；历史订单的商品名称、单价与金额快照保持不变。未开放上下架、补库存或售后。

## 酒店布草订单与退污联动

- 酒店端列表与详情统一为“布草订单”，平台及工厂端保留原名称；新建与示例订单采用同一卡片和对应订单详情。
