# 对话过程反馈：接口依据与适配说明

本文件供前后端联调使用；产品行为以同目录 `PRD.md` 为准。原型仅消费本地合成事件，不访问生产接口，也不新增生产接口。用户侧仅替换原“思考中”状态行，首个非空正式回答到达即由正文替换；不展示过程列表或历史入口。

## 1. 依据与证据边界

- 接口依据：[会展智媒通接口文档](https://share.commind.com/wiki/external/org/CdYM72gy/#/page/AeEJnnvt/7gNPkL5b)。下表属于文档字段的展示映射，不代表所有分支均已实测。
- 页面观察（2026-09-20）：在展商首页点击“今天有哪些值得推荐的活动安排？”后，早期跨数分钟多次检查显示“思考中”及停止按钮；最终检查已显示正式答案及赞、踩、语音播放、发送按钮。浏览器 info / warn / error 日志为空。间隔采样只证明该轮从等待进入正文完成，不能确定首字耗时、是否逐字流式或等待原因。
- 实测页面返回摘录（非 SSE、非业务真实性背书）：问题为“今天有哪些值得推荐的活动安排？”；答案称当天无正式展览、建议场外活动，并表示可继续查询后续展馆日程。活动日期和业务事实未核验，不采纳为原型事实。
- 用户另提供一组“服务台”问答的 Network / EventStream 截图，与上述“今天活动”请求不是同一轮。第 4 节为截图可读字段的脱敏转录；截图行有截断，尚未取得完整原始 SSE，不能把转录当作完整 JSON 响应。第 5 节另列**合成契约样例**，两者不混同。
- 不保存带鉴权参数的页面 URL、API Key、登录凭证、原始用户身份信息或未经脱敏的网络日志。

## 2. 字段到展示行为的映射

下表中的过程文案均仅适用于首个非空正式回答出现之前。首次非空 `summary` 正文到达后锁定本轮 `answerStarted`：隐藏状态与等待提示，只保留流式正文及末尾生成光标；任何后续工具、规划、空白片段或停顿都不得恢复过程行。正常结束移除光标，错误保留正文或显示无正文错误提示。

| 文档字段 / 值 | 前端处理 | 用户侧展示 |
| --- | --- | --- |
| `stage: planning` | 识别规划阶段；该阶段 `content` 不进入正式答案 | 存在明确阶段事件时可显示“正在理解问题” |
| `stage: summary` | 识别总结阶段；非空 `content` 进入本轮正式答案 | “正在整理回答”；首段到达即显示正文 |
| `content` | 按文档增量示例处理总结阶段文本；生产增量方式仍需核实 | 增量答案，不等待过程区动画 |
| `reasoningContent` | 不渲染、不进入答案或当前状态；缺失为正常分支 | 不展示思考原文 |
| `toolCallStatus: START` | 内部创建或更新该次调用的执行状态 | 仅更新当前状态行；未知名称使用“相关服务” |
| `toolCallStatus: SUCCESS` | 内部标记该次调用已取得成功结果 | “查询完成” |
| `toolCallStatus: END` | 记录调用结束事实，不推断成功或失败 | 已有成功 / 失败状态保留；尚无结果则显示“查询已结束，结果待确认” |
| `toolCallStatus: FAILURE` | 内部标记该次调用失败；不自动判定整轮回答失败 | “本次查询未成功”；后续回答仍可继续 |
| `planId`、`toolCallId` | 结合前端本轮请求标识关联事件；不同轮次隔离 | 不向用户展示内部标识 |
| `isEnd` | 结束本轮接收；检查正文与错误状态 | 有正文且无异常时移除生成光标；空正文时移除状态行并显示“未获得回答” |
| `isError` | 明确整轮错误；保留已收到正文 | 有正文时标注“回答未完成”，无正文时显示失败提示 |
| `finishReason: length` | 作为输出截断处理，不能显示完整回答已完成 | 保留正文并标注“回答未完成” |

文档简例未携带 `stage`，而字段表区分规划和总结阶段，两者存在适配差异。不得默认把所有无 `stage` 的 `content` 当作答案；生产接入前必须由服务方确认兼容规则。原型采用归一化的 `planning`、`summary`、`content` 等本地事件，`content` 仅代表已确认的正式答案；这些事件不是原始 SSE 解析器，不掩盖这一缺口。

## 3. 归并、顺序与终态

调用记录、计划顺序和计时均为内部计算依据，不构成用户可查看的过程历史。用户侧只显示当前一句状态；查询并发时优先显示执行中数量，无执行中查询时使用最近有效阶段或查询结果。空字符串或仅空白的正文不触发首字切换。

- 每次发送生成独立轮次标识。调用关联键至少包含“轮次 + `planId` + `toolCallId`”，不能只按工具名称合并；同一工具的两次调用内部独立保留，按首次出现顺序记录，不能因工具同名合并。该集合只供状态计算，不渲染为步骤列表。
- 重复的同一调用状态幂等更新，不重复计算调用，不重复刷新“最后进展时间”。没有调用唯一标识时不能假造可追踪的调用身份，保留概括状态并记录适配缺口。
- `SUCCESS → END` 保持成功，`FAILURE → END` 保持失败；只有 `END` 时内部保持结果未确认。已失败或成功的调用收到迟到 `START` 时不回退执行中。相互矛盾的成功 / 失败终态不猜测覆盖，须核查服务事件顺序与重试标识。
- 本轮接收结束后忽略该轮迟到事件，不更新下一轮。重新提问创建新轮次，历史未完成内容保留。
- 文档有正文增量示例，截图可见总结正文分片；完整生产响应的增量 / 累计约定仍需核实。没有事件序号时不能按正文文本去重：重复文字可能是合法内容。也不能承诺无序分片可正确重排；断线续传、重放与事件唯一标识需联调确认。
- “最后进展”仅由首次确认的受理 / 服务处理状态、实际新阶段、调用状态变化或非空答案更新推动；心跳、重复通知和本地计时不算进展。无进展 10 秒 / 30 秒只增加等待提示，不推进步骤或判定失败；首个非空正文出现后完全隐藏过程与等待提示，只保留正文及生成光标。内部总耗时从发送开始，到本轮明确终止为止；不常驻展示，只在首字前的长等待提示中显示无进展时长。
- 明确网络中断、`isError` 或截断结束保留正文并标注未完成；正常结束但无正文显示“未获得回答”。单个工具失败不是整轮错误。

首个可见事件到首正文为 **6.927 秒**，到结束为 **6.975 秒**。这是截图覆盖区间，不是用户发送到首字耗时，也不是服务 SLA。原型选择“截图时间线复现”并开始演示后重放主要事件节奏；从首个可见事件记为 0 秒，不补造发送到首事件的间隔。正文采用演示内容，内部拆分间隔仅用于演示，不声称逐包原样复现，也不背书截图中的业务信息。

新增适配约束：

- `planStatus`、`globalPluginStatus` 和插件事件来自截图观察；接口文档通用字段表没有明确给出这些状态枚举，不能将样本枚举当作完整协议。
- `planStatus: COMPLETE` 只表示该计划完成，绝不表示整轮结束；截图存在 p1 → p2 → p3 多计划循环。`globalPluginStatus: PROCESSING` 不能单独证明某个具体服务开始或查询成功。
- 插件事件需按轮次、所属 `planId`、`callId` 与已有 `toolCallId` 核实归属。归属确认后更新已有调用状态，避免 tool 与 plugin 重复计为两次查询；不能仅凭相同名称或相近时间强行关联。
- 本样本的 `code: 200` 及成功消息提示返回结果，但只有在确认对应插件业务成功语义后，适配层才可提升为 SUCCESS。截图未完整辨认出工具 SUCCESS 状态行，不能声称四种工具状态均已实测；原型截图重放在内部保守保留 END 的“结果待确认”，只在首字前且无其他活动时用作当前状态，不展示历史步骤。

## 5. 合成契约样例（非实测响应）

以下只突出适配涉及的字段，省略真实协议封装、请求头及无关字段；不是可直接调用生产接口的协议定义。

```json
[
  {"planId":"demo-plan-1","stage":"planning"},
  {"planId":"demo-plan-1","toolCallId":"demo-call-1","toolCallStatus":"START"},
  {"planId":"demo-plan-1","toolCallId":"demo-call-1","toolCallStatus":"SUCCESS"},
  {"planId":"demo-plan-1","toolCallId":"demo-call-1","toolCallStatus":"END"},
  {"planId":"demo-plan-1","stage":"summary","content":"可先关注当天的主题活动。"},
  {"planId":"demo-plan-1","stage":"summary","content":"具体时间请以现场公告为准。"},
  {"planId":"demo-plan-1","isEnd":true}
]
```

原型还合成直接回答、多工具执行、工具失败后继续回答、无思考内容、长等待、部分答案后中断、空答案结束等场景。场景播放计时仅用于演示事件到达时间；等待提示本身不会产生业务步骤。模拟活动文案不作为真实展会信息。

## 6. 最小联调检查与验证缺口

| 必查项 | 当前证据 | 生产适配通过标准 |
| --- | --- | --- |
| 规划 / 总结阶段与正文 | 文档声明；截图可见多计划与 summary | 取得完整脱敏事件时间线，确认无 `stage` 兼容规则及计划状态枚举 |
| 正文增量与重放 | 文档增量示例；截图可见正文分片 | 确认片段 / 累计模式、事件序号及重复事件处理；合法重复文字不丢失 |
| 调用关联与工具结束 | 截图可见 START、END 和插件结果；SUCCESS / FAILURE 未完整实证 | 实际覆盖四种状态；确认 tool / plugin 关联及业务成功判据，避免重复计算查询与 END 误判成功 |
| 结束、错误与截断 | 截图可见 `isEnd: true` 与 `finishReason: stop`；异常仍为文档声明 | 核对真实类型、组合与优先级；覆盖错误、截断、空答案及部分正文 |
| 并发、迟到与断线 | 未取得原始流 | 明确序号 / 重试边界；旧轮次不污染新轮次，迟到 START 不回退终态 |
| 四角色适用性 | 已观察四角色真实首页；过程反馈共用仍为产品规则，未取得四角色完整生产流 | 各角色权限下显示规则一致，工具业务名称来自已确认映射 |

新增必查：首个非空正文出现时状态行和等待提示同步移除；没有任何展开或历史过程入口；首字后的工具事件、规划事件、空白片段与长停顿均不恢复过程。正文结束移除生成光标，异常时不恢复过程，并保留用户上翻阅读位置。

本地原型验证只证明显示规则可演示，不代表生产流已通过联调。取得真实响应后应补充脱敏字段样本、到达顺序和耗时证据，并将已验证条目逐项更新。

## 7. 四角色真实首页还原依据

- 观察日期：2026-09-20；来源页面：[会展智媒通移动端](https://voicehub.commind.com/hzzx/mobile/)。按用户提供的四个入口分别观察 `role=visitor`、`role=exhibitor`、`role=trader`、`role=media`，不在交付材料中保存带鉴权参数的 URL。
- 四角色欢迎语均为“Hi，我是「数小潮」”，共用吉祥物；普通用户、展商、客商、媒体主题分别为蓝、橙、紫、绿。角色欢迎副标题、服务卡片、功能入口、推荐问题与快捷项以 PRD 第 1.4 节逐项记录为准。
- 四角色功能入口数量分别为 8、9、6、7。首页内容为实际页面观察所得，不由角色名称推测；展商页出现媒体报道与宣传稿推荐问题，仍保留观察到的原文，不自行改写。
- 从页面实际加载资源中提取 PNG 与两个行内 SVG，保存到本地 `assets/`，去除构建哈希后保留可读名称。共享资源去重保留；未复制加载动画、样式表、favicon、资源清单或带鉴权链接。原型素材使用本地文件，不依赖生产热链。
- 当前仅还原真实首页及对话容器，过程状态仍使用既有本地合成事件；没有接通原页面的业务入口、实时信息查询、登录授权或真实语音能力，不能把首页还原当作生产功能联调通过。
- 默认普通用户首页，禁止加载时自动播放。角色选择器和场景选择器均属于外部评审工具；切换角色清空演示轮次与草稿并停止旧播放。推荐问题或外部开始演示触发既有状态机，沿用单轮在途、等待计时、异常处理、轮次隔离及阅读保护规则。
