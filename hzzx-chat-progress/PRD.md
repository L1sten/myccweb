# 会展智媒通对话过程反馈需求文档

版本：v1.3　需求范围：用户输入问题至本轮回答完成或异常终止

## 1. 产品概述

### 1.1 背景与目标

对话等待期间持续显示“思考中”，用户无法判断问题是否收到、查询是否推进或回答是否开始。本模块将等待反馈细化为有事实依据的当前状态，让用户尽早看到有效反馈，并在答案到达后立即阅读。

- 发送后立即呈现用户问题和提交状态。
- 首段回答前在原“思考中”位置显示当前一句状态；首段回答出现后由正文替换。
- 正式回答到达即显示；无过程信息也能正常回答。
- 对长等待、查询失败、回答中断和空回答给出明确且真实的反馈。

### 1.2 使用场景与起止边界

用户在现有对话输入框中输入问题，发送后等待处理，并阅读逐步生成的回答。需求从输入问题开始，到本轮回答完整结束或明确异常终止为止；异常后的重新提问作为恢复操作纳入本期。规则适用于现有各角色的问答，不重新定义角色页面或权限。

### 1.3 本期范围与约束

- 覆盖问题输入与发送、提交反馈、首段回答前的状态提示、正文生成与完成、异常恢复及本轮阅读保护。
- 首段回答前只更新原“思考中”位置的一句状态；首个非空正文出现后由回答替换，不保留过程查看能力。
- 不展示思考原文、内部服务标识、原始业务数据或鉴权信息，不使用虚构进度或预计完成时间。
- 不涉及首页、角色切换、欢迎语、功能入口、推荐问题配置、快捷服务、语音、多语言及回答完成后的评价或分享功能。

## 2. 全局交互规则

### 2.1 页面结构与顺序

对话区域按轮次先后排列。每轮发送后，在原“思考中”位置呈现当前一句状态；首个非空正式回答到达时，正文立即替换状态行。之后仅展示流式正文及末尾生成光标，异常说明位于该轮回答之后。状态只属于当前轮次，不新增独立过程卡片或历史过程入口。

### 2.2 问题输入与提交

问题内容字段：

- **展示规则**：使用现有对话输入框，沿用现有引导文案；输入内容可编辑，发送后在本轮用户消息中完整展示，长内容正常换行。
- **交互规则**：支持输入、修改、清空和发送；空输入或仅空白内容不可发送。生成期间可编辑下一条问题，但不能发起另一轮。
- **数据规则**：以用户本次提交的问题作为本轮输入，不与其他轮次混合；不涉及筛选或排序。

提交与轮次规则：

- 非空问题可发送；仅空白内容视为空，不创建轮次。
- 发送后立即创建用户消息，显示“正在理解问题”，清空本次输入。
- 同一会话只允许一轮在途。生成期间允许编辑下一条问题，但禁用发送，提示“回答完成后可发送”。
- 重复点击发送不创建重复轮次；已提交问题在本轮中只读。
- 明确结束、失败或空回答结束后恢复发送。长等待本身不解除在途状态。
- 重新提问使用原问题创建新轮次，旧轮次及已有内容保留；不覆盖输入区正在编辑的草稿。

### 2.3 空状态、权限与排序

- 问题发送后，从“正在理解问题”开始等待；无明确进展时不补造后续流程。
- 对话轮次按发送顺序排列；每轮仅显示当前一句状态，不显示步骤列表。
- 本模块无筛选、分页、批量操作和额外权限点。用户只能查看当前授权会话中的内容。
- 无对话访问权限时沿用原有访问限制，不单独暴露处理过程。

## 3. 模块一：首段回答前的当前状态

### 3.1 当前状态行

- **展示规则**：仅替换原“思考中”那一行，显示当前一句业务状态；长文案自然换行。无长等待时不单独显示耗时。首个非空正式回答到达即移除状态行及等待提示，由正文占用该位置；不保留独立过程卡片、步骤列表、展开按钮或历史过程入口。
- **交互规则**：状态只读，不可点击查看过程。状态更新不影响用户阅读位置。首段回答出现后，本轮不再恢复状态行；后续工具活动、正文间歇、空白内容或长等待均不能让状态重新出现。
- **数据规则**：取数范围为本轮处理信息，不涉及筛选或排序。发送后默认显示“正在理解问题”，作为初始等待文案，不表示已确认服务受理或分析阶段开始；收到受理通知但没有新阶段时保持该文案，不展示提交或受理过程。后续只有实际进入对应阶段，才显示“正在查询相关信息”或“正在整理回答”。多个查询同时执行时显示“正在查询相关信息（N 项）”，N 仅计当前执行中的查询；未知服务统一使用“相关服务”，不暴露内部名称。

### 3.2 真实进展与状态归并

- 真实进展表明正在匹配常见问题时显示“正在匹配常见问题”；正在检索资料时显示“正在检索相关资料”，不提前预测进展。
- 只有笼统服务处理通知、无法确定具体查询对象时，显示“正在处理相关信息”。
- 首次实际分析显示“正在理解问题”；再次实际进入分析时显示“正在进一步分析”。分析结束仅表示该阶段结束，不代表整轮回答完成。
- 同一次查询的不同来源通知合并判断，不重复计算执行数量；不同查询分别判断状态，但不向用户列出历史明细。
- 当前有查询执行时显示其对应查询状态；否则显示最近一次有效阶段或查询结果。查询完成、失败、结束只描述查询自身，不表示整轮回答完成。

| 已知事实 | 首段回答前的状态文案 | 后续判断 |
|---|---|---|
| 查询实际开始 | 正在查询相关信息，或已确认的业务文案 | 等待真实结果，不提前标为完成 |
| 明确取得成功结果且无其他执行中的查询 | 查询完成 | 之后按实际新阶段更新，不由迟到的开始信息倒退 |
| 明确查询失败且无其他执行中的查询 | 本次查询未成功 | 仍可继续处理与生成回答，不立即终止整轮 |
| 仅确认执行结束、未确认结果且无其他执行中的查询 | 查询已结束，结果待确认 | 不推断成功；之后按真实进展更新 |

- 重复进展不改变已确认状态、不重置等待计时，也不增加正在执行的查询数量。
- 结果先于开始信息出现时，以已知结果判断；迟到的开始信息不使状态倒退。
- 同一次查询已明确失败后，不被迟到的成功信息覆盖；实际再次执行视为新的查询。
- 首段回答出现后，这些进展仅参与内部状态判断，不再显示任何过程状态。正常答案结束不能反推所有查询均成功。

### 3.3 长等待提示

- **展示规则**：仅在首段回答尚未出现时，连续 10 秒没有有效进展，在当前状态旁补充“暂未收到新的处理进展，已等待 X 秒”；连续 30 秒后补充“本次等待较久”。不常驻显示总耗时。首个非空正文出现时，等待提示随状态行一起移除。
- **交互规则**：等待提示只读；恢复有效进展后移除提示，不移动阅读位置。首段回答出现后，即使正文长时间未继续增长也不恢复等待提示，保持已有正文与生成光标。
- **数据规则**：等待时长从发送或最近一次有效进展起计。有效进展包括首次受理确认、新的实际阶段、查询状态实际变化或新的正式回答内容；重复通知、无内容的连接维持和计时刷新不计入。内部总耗时仍从发送起计，明确结束或失败时冻结，与无进展时长分别计算，不混入下一轮。等待秒数按完整秒显示，不涉及筛选或排序；计时异常不得显示负值或编造数字，必要时显示“计时暂不可用”。
- 10 秒与 30 秒只控制首段回答前的等待提示，不触发虚构进展、自动重试或失败判定。

## 4. 模块二：正式回答与阅读保护

### 4.1 正式回答正文

- **展示规则**：首个非空正式回答到达即呈现，同时移除当前状态行与等待提示，随后新增内容持续显示；不等待查询全部结束。生成中仅保留正文和末尾生成光标，不额外显示“正在生成回答”状态。过程文字不得混入正文。长文本、段落和列表正常换行。
- **交互规则**：生成中允许阅读已显示内容；空字符串或仅空白内容不能触发首段出现。异常时保留已收到的正文并标注“回答未完成”，不恢复过程状态。
- **数据规则**：仅采用本轮正式回答内容；理解、规划和过程摘要不作为正式答案。不涉及筛选；按正文原有顺序累计呈现，不重复追加已经显示的内容。不同轮次内容不得合并。

### 4.2 回答状态

- **展示规则**：有正文且收到明确完成信息，移除末尾生成光标，保留完整正文；不增加过程完成条。只有正文暂时停止增长，不视为完成。失败时显示“回答未完成”；结束但无非空正文时显示“未获得回答，请重新提问”。
- **交互规则**：回答成功完成后结束生成状态；失败或空回答结束后允许重新提问。异常说明不影响正文阅读，结束或失败后不恢复过程状态。
- **数据规则**：状态仅针对本轮，以正文是否存在及明确终止事实判定，不涉及筛选或排序。终态确定后不再接收迟到内容改变本轮；新一轮单独计算状态。

### 4.3 阅读位置与新内容入口

- 用户位于对话底部时，新增内容持续跟随显示。
- 用户主动上翻后停止自动跟随；状态变化、计时刷新和回答追加均不抢回底部。
- 离开底部且有新内容时显示“回到最新”；点击后定位最新内容并恢复跟随。
- 用户自行回到底部后同样恢复跟随并隐藏入口；纯计时刷新不视为新内容。

## 5. 模块三：异常反馈与操作

### 5.1 异常分类

- **提交失败**：明确提交失败时显示“问题提交失败，请重新提问”，保留用户消息，不显示已开始查询。
- **单次查询失败**：首段回答前按当前查询事实更新状态，首段回答后不显示过程状态；仍有处理活动时继续等待或生成，不立即终止整轮。
- **连接中断或整轮处理错误**：终止本轮生成并移除状态行或生成光标；无正文显示“回答中断，请重新提问”，有正文保留并标注“回答未完成”，不恢复过程状态。
- **空回答结束**：移除状态行；明确结束但正文为空或仅空白时显示“未获得回答，请重新提问”，不显示回答完成。
- **长等待**：首段回答前按阈值补充等待提示；首段回答后保留正文与生成光标，不恢复等待或过程行；不推断网络断开或服务失败。
- **缺少过程内容**：保持可证实的受理或等待状态；正式回答到达后直接显示，不补齐“理解—查询—整理”流程。

### 5.2 操作状态矩阵

以下操作均沿用现有会话权限，不新增权限项；不可访问会话时不展示本模块操作。

| 操作 | 展示与可用条件 | 禁用或隐藏规则 | 点击反馈与结果 |
|---|---|---|---|
| 发送 | 输入非空且无在途轮次 | 空输入禁用；在途时禁用并说明“回答完成后可发送” | 立即追加用户消息与提交状态，无二次确认 |
| 重新提问 | 本轮明确失败或空回答结束后展示 | 另有轮次在途时禁用并说明原因 | 原问题创建新轮次，旧内容保留，无二次确认 |
| 回到最新 | 用户离开底部且有新内容时可用 | 已到最新位置时隐藏 | 滚动到最新内容并恢复跟随 |

- 本期不提供取消生成、编辑已发送消息、自动重试和批量重试。
- 重新提问失败按新轮次异常处理，不反复自动发送；用户现有草稿保持不变。

## 6. 验收标准

### 6.1 场景验收

| 场景 | 必须观察到的结果 |
|---|---|
| 输入与提交 | 空值及仅空白内容不可发送；有效问题发送后立即显示用户消息与提交状态；生成期间重复发送不创建新轮次 |
| 直接回答 | 提交后立即显示当前状态；首个非空正文立即替换状态行，无步骤列表；明确结束后移除生成光标 |
| 单工具查询 | 首段回答前按真实查询进展更新同一状态行；首段正文出现即移除该行 |
| 多工具执行 | 仅显示当前一句状态，并发执行数量正确；不生成多行步骤清单 |
| 工具失败后继续回答 | 首段前按当前事实反馈失败或其他活动；正式答案仍可正常生成，首段后不恢复工具状态 |
| 无思考内容 | 无空白思考区；真实状态正常显示，首段出现即替换 |
| 多轮分析与查询 | 首段前随真实进展更新理解问题、常见问题匹配、进一步分析、资料检索等当前文案；阶段结束不误判整轮完成 |
| 长等待 | 首段前 10 秒无进展显示等待秒数，30 秒补充较久提示；首段后不再显示过程或等待提示 |
| 部分答案后中断 | 正文保留并标为未完成，生成光标移除，不恢复过程行；可重新提问 |
| 空答案结束 | 移除状态行，说明未获得回答，不显示成功；可重新提问 |

### 6.2 一致性与边界验收

- 首个非空正式回答出现时，当前状态和等待提示同时移除；全程没有独立过程卡片、步骤列表、展开按钮或历史过程入口。
- 首段后的工具事件、再次分析、空白片段和正文停顿均不能恢复状态行；生成中只有正文与末尾生成光标。
- 重复开始、结果或结束通知不重复计算查询，不重置等待时长；同一次查询不同来源的通知合并判断。
- 笼统服务处理通知只更新当前文案；多轮分析依据实际阶段计算，不补造进度。
- 仅收到查询结束信息不显示成功；结果先到、开始后到时状态不倒退。
- 新轮次开始后，旧轮次迟到信息不混入新轮次，也不改写已终止的旧轮次。
- 一轮生成时重复发送无效，可编辑草稿；生成结束后恢复发送，重新提问不覆盖草稿。
- 总耗时与无进展时长分别计算，首段前 10 秒和 30 秒边界正确；终态计时冻结，不常驻展示总耗时。
- 上翻阅读时任何增量变化不抢滚动；回到最新后恢复跟随；长文本正常换行。
- 四角色反馈规则一致且不扩大原有数据可见范围；业务界面不出现内部标识、原始返回或鉴权信息。
